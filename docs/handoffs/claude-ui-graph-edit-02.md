## UI-GRAPH-STABLE-03：关系增删后节点位置不动（2026-11-11 追加）

用户确认接着处理。规格见 `specs/course-knowledge-graph.md`「关系增删后节点位置不动」。

- **原因**：`useGraphLayout` 监听整个布局源，草稿图里任何变化（含保存中的临时线）都会把位置清空重算，`GraphCanvas` 随之拆掉重建。
- **改法**：`useGraphLayout` 新增 `stable` 选项（教师页开启）。已有位置在“只增删改关系、或删除知识点”时继续使用；出现新知识点、知识点换章节、章节顺序变化才重新计算。新增返回值 `stale`（位置是按早先的关系排的）与 `relayout()`；教师页在 `stale` 时显示“重新排布”。
- **文件**：`composables/useGraphLayout.ts`、`views/TeacherGraphView.vue`；测试 `graph-layout-composable.test.ts` 追加 5 条（先写、确认 4 条失败后再实现）、`h14.test.ts` 追加 1 条。学生页不传该选项，行为不变（有回归用例）。
- **真实画布实测**（临时预览页，接口为替身，已删除）：从连接柄拖线新建“队列 → 栈顶（包含）”后，所有节点的屏幕位置与之前完全一致，新线画出，画布栏出现“重新排布”；点击后整张图重新整理、按钮消失。
- **已知取舍**：沿用旧位置时新线可能交叉或绕远；新建知识点仍会触发整张重排（新节点需要位置，没有做增量放置）；拖动过的节点位置仍然不持久，下一次数据更新会回到布局给的位置（既有行为）。

### 复核中发现并修掉的

1. **工具条一打开就被收起**（回归，上一轮引入）：给被点中的线加粗会触发一次数据更新，画布随后回报缩放值，页面把它当成“画布移动”而收起工具条。临时预览页是在加这个功能之前测的，所以没发现。改为只在 G6 的 `aftertransform`（真正的平移、缩放）时通知页面：增强层新增 `onTransform`，`GraphCanvas` 的 `viewChange` 改由它发出；补了回归测试（数据更新后不通知，`aftertransform` 才通知）。
2. **成环提示里环路写了两遍**：关系组合式的错误文案里已经带了环路，浮层又追加了一遍。改为有文案时只显示文案。
3. **“就此提问”按钮显示成深绿色**：被改版后的主按钮规则盖住。按同样的前缀提高了优先级，现在是向日葵黄。

### 复核中观察到、未处理的

- **改类型或反转成功后工具条会自动收起**：后端按“类型 + 端点”重新派生关系编号，原编号不再存在，工具条找不到对应的线。行为上可以接受（一次操作完成即收起），但和自动化测试里的替身不一致（替身保留编号，工具条留着）。
- **节点标签会挡住关系线的点击**：线从标签文字下面穿过的那一段点不中线，点到的是节点。贴近节点处需要点在没有文字的线段上。
- 没有制造修订冲突与网络失败（这两种仍只有自动化测试覆盖）。
