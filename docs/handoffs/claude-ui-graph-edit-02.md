## 背景

2026-11-10 的体验差距分析里，教师编辑是“面板 + 模式”而不是直接操作。用户确认了设计样例和三项取舍：只有从连接柄开始拖才是连线（另有点选路径）；拖动中做前端成环预判；关系线删除不弹确认、给可撤销提示，节点删除保留现有确认。规格见 `specs/course-knowledge-graph.md`「画布上的直接操作」。

## 交付物

| 能力 | 行为 | 主要文件 |
| --- | --- | --- |
| 关系线工具条 | 点击关系线，在点击处上方出现类型下拉、反转（“相关”没有）、删除；对应的线加粗；点空白、Esc、画布移动时收起 | `components/canvas/CanvasEditLayer.vue`、`composables/useCanvasEditing.ts` |
| 可撤销的删除 | 删除不确认；成功后 6 秒内可“撤销”，撤销是按原类型和端点重新建一条 | `composables/useCanvasEditing.ts`、`composables/useRelationEditor.ts`（`createBetween`） |
| 节点菜单 | 右键或悬停后点“⋯”：查看详情、编辑知识点（E）、从这里连线…（L）、删除…；前两项与删除都经过“未保存修改”确认，删除打开编辑面板里现有的确认 | 同上；`components/NodeEditor.vue` 暴露 `requestDelete` |
| 拖线 | 悬停节点时右侧出现连接柄，只有从它开始拖才是连线；虚线跟随指针，目标显示外环；松开后选关系类型才发请求 | `CanvasEditLayer.vue`、`graph/hitTest.ts` |
| 点选连线 | 菜单“从这里连线…”后点击目标节点；不改变当前选中；画布移动不打断 | `useCanvasEditing.ts`、`views/TeacherGraphView.vue` |
| 成环预判 | 目标沿未驳回的前置关系能回到起点时，拖动中标出“前置会形成环”，类型选择里“前置”不可选，其余可选 | `graph/cycle.ts` |
| 就此提问 | 学生预览卡新增按钮，进入问答页预填“请讲解一下「名称」”，光标进输入框，不自动发送 | `components/GraphPreviewCard.vue`、`views/StudentGraphView.vue`、`views/ChatView.vue` |

### 真实画布实测（2026-11-11）

本机 Docker 当时未运行，隔离后端没搭起来。改用临时预览页：**真实的教师图谱页 + 真实的 G6 画布**，五个接口用内存假数据并记录写调用；1440×900。预览文件用完已删除、未提交。

| 操作（真实鼠标） | 结果 |
| --- | --- |
| 点击“栈 → 括号匹配”关系线 | 工具条出现在线旁，类型为“前置”，有反转 |
| 点“删除”再点“撤销” | 依次记录一次删除、一次新建（同类型同端点），撤销提示消失 |
| 指针停在“队列”上 | 节点右侧出现“⋯”圆钮和绿色连接柄 |
| 从连接柄拖到“栈顶”后松开 | 出现类型选择“队列 → 栈顶”；点“包含”后记录一次新建 |
| 在节点上点右键 | 出现该节点的菜单，四项齐全，没有浏览器自带菜单 |

实测中发现并修掉的：悬停工具和菜单的样式被教师页的通用按钮规则盖住（连接柄显示成白色方块），已把浮层样式的选择器加倍并先清掉通用规则带来的外观；规格里“被点中的线加强调”原先漏做，已补。

## 风险与已知限制

- **新建或删除关系后整张图会重新布局**（节点位置变化）。这是既有行为（布局随数据重算），不是本任务引入的，但直接操作让它更显眼：刚连完线，节点就挪了位置。建议作为后续任务处理（增量布局或保持已有节点位置）。
- 撤销删除是重新建边：原关系的编号、来源片段与审核状态不恢复，新关系是人工、待审核状态。界面提示里写明了。
- 成环预判只看前端手里的草稿图；别人同时改图时可能与后端结论不同，以后端为准。
- `TeacherGraphView.vue` 里 `canvasGraph` 引用了定义在其后的 `editing`（计算属性惰性求值，运行时没问题），重排代码时要留意顺序。
- 教师页菜单没有设计稿里的“只看相邻”：教师页目前没有局部视图，未做。
