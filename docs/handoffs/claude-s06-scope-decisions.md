## 关键决定

1. **不改写 ADR-005，而是写 ADR-006 修订它。** ADR 是决策记录，改写会抹掉「当初为什么那样决定」。ADR-005 保留原文并在头部标注第 2 条已被取代，其余内容（状态机序列、`persisting`、枚举一次定稿原则）仍然有效。
2. **取消是协作式的**：端点只置「已请求取消」标记并立即返回，worker 在阶段边界检查后进入 `cancelled`，不强杀进程、不中断进行中的单次模型调用。同时定死三条边界——已终态取消返回明确错误码而非静默成功；取消与完成竞争以先到终态者为准；部分写入必须清理或标为废弃草稿，**不留半截图谱给教师看到**。
3. **加分项排在最后，且受 ADR-003 约束**。M1-07 优先级低于 M1 其余全部任务（M0 已逾期 3 天，不能让加分项挤占主链路）。讲解和练习题比问答更容易让模型自由发挥，因此明确要求基于课程原文并给出来源，资料不足返回 `NOT_COVERED`，不得凭常识编题。
4. **M0-07 扩大并前置于 M0-04a**。`src/contracts/README.md` 现在有两处失效表述，若不先修，M0-04a 起草契约时会照抄错的状态机语义。
