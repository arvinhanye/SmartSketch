## 行为与数据流

1. 消歧新任务启用 `WindowPolicy`。完整请求按渲染后的 UTF-8 字节、每条消息 256 包装余量、`4 × max_output_tokens` 输出预留检查；这不是模型 tokenizer 或有效上下文保证。
2. 实体抽取先按原块字符范围规划带重叠的窗口；关系抽取优先使用完整实体表，放不下时逐个完整实体对覆盖全部来源。单卡、输出预留、窗口总数超限均明确失败，不截定义、不漏掉实体对。
3. 关系窗口预规划先于小节内语义分析。确定超限的小节没有无效语义调用；实体、关系、修复、补漏的物理请求均保留原调用预算、取消、租约、凭据和审计保护。
4. 可选补漏按每轮已有实体表再次有界分窗；已有候选全部保留，局部提示采用当前子窗中的候选及换算后的坐标。主抽取和补漏累计共享窗口上限；已知必需最少窗口超限时不启动抽取。新增实体使后续轮次超限时，在该轮调用前结束，早先发生的调用仍记账。
5. 所有证据还原到原始块 ID、字符位置及页码/章节；重复窗口只按同一出现和内容去重。任一窗口失败，整个块/小节不提交半份候选；现有 L2 可能重做该单元早先窗口，没有新增重试层或并发池。
6. 检查点 `metadata` 保存 `window_policy`、`window_coverage`，其中包括内容/模型/提示词摘要、主抽取及补漏计划/完成数和失败原因。失败的 `result` 仍为 NULL。接管固定已存策略；旧无策略任务走旧路径；混合策略拒绝执行。
7. 全局合并摘要纳入抽取检查点。失败单元或不完整窗口产生 `partial / extraction_incomplete`，不执行合并判断、不产生合并组、不把技术缺口塞进人工疑似重复队列。可用原始节点仍进入草稿，审核摘要显示具体原因。完整窗口仍能走正常自动合并与审核流程。

## 配置与速度

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `DISAMBIGUATION_EXTRACTION_MAX_INPUT_BYTES` | 24000 | 完整请求预算，含输出预留 |
| `DISAMBIGUATION_EXTRACTION_MAX_WINDOWS` | 64 | 每单元每次尝试的累计窗口上限，含补漏 |
| `DISAMBIGUATION_EXTRACTION_OVERLAP_CHARS` | 512 | 同块相邻窗口的字符重叠 |

短输入仍走一个主抽取窗口。窗口在原有任务池内顺序消费；大实体表的全对检查可能明显增加调用，先进行组合数量和来源窗口预检，不物化无界二次组合。没有用减少覆盖换速度，也未证明真实模型的生成时延达标。
