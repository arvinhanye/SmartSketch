## 3. 缺陷与验收

### F1 P1 长按 M 会自动合并下一条

**位置：** `src/frontend/src/views/ReviewView.vue:169`，尤其 `onKeydown` 的 M/N 分支。

**复现：** 准备至少两组可成功合并的候选，展开第一组；按住 M，使第一笔请求完成、页面自动前进后仍产生重复 `keydown`。Chrome 记录了 `repeat=false` 与 `repeat=true` 两次 M 事件，对应两笔合并请求均为 200，节点共减少 2 个。

**原因及影响：** 只检查 `busy`，不检查按键重复。第一笔结束后 busy 解除，持续按住的同一个键被当作对下一条的新决定，构成用户未逐条确认的连续写入。

**修复要求：** 写入快捷键拒绝 `event.repeat`，确保下一次写入来自释放后重新按下的独立操作；保留请求在途守卫。对 N 使用同样保护。无需增加每次点击的额外确认弹窗。

**验收：** 首次 M 成功且自动前进后，重复 M 事件仍只产生 1 次写请求；释放后再按允许处理下一条。N 同样覆盖；鼠标连点、请求在途、输入法组合和修饰键守卫不退化。测试必须跨越第一次请求完成的时间点，不能仅验证 busy 期间。

### F2 P2 有来源的节点显示来源 0 处

**位置：** `src/frontend/src/components/review/DuplicateCompare.vue:38`，`sources: node?.source_refs?.length ?? 0`。

**复现：** 打开有来源的候选对。`GET /api/v1/courses/{cid}/graph` 的实际节点不带 `source_refs`；同一节点 `GET /api/v1/courses/{cid}/kp/{kid}` 返回 1 条来源，但卡片显示“来源 0 处”。另一个合并后的节点详情返回 2 条来源，同样不能靠现有草稿图字段正确计数。

**原因及影响：** 把“未在这个响应中提供来源”当成“没有来源”，直接干扰教师判断。

**修复要求：** 使用现有节点详情接口，在展开候选时按需读取两侧详情；区分加载中、读取失败和真实 0。按课程、节点及修订缓存，课程切换/候选切换时隔离迟到响应，成功合并后失效相关缓存。不要为每一条折叠候选预取全量详情。

**验收：** 使用不含 `source_refs` 的真实形状草稿响应；详情 1/2/0 条来源分别正确显示；请求失败不能显示 0；快速切换候选/课程不会串来源，重复展开不造成无意义请求。完整原文引用展示属于后续增强，不要求本修复新增后端 API。

### F3 P2 404 未合并却记为已合并

**位置：** `src/frontend/src/views/ReviewView.vue:148` 的 `settle`；`useReview.ts` 中 `resolve` 对 `NOT_FOUND` 的处理。

**复现：** 页面展开一对候选；另一个 API 客户端将同一对标记为不是重复（200）；原页面再点合并，服务端返回 404。等待页面稳定后，两节点仍存在，页面提示“该条已不在队列中……”，但“本次已处理”写入“已合并”。

**原因及影响：** 组合式函数返回 `void`，页面把“该条离开队列”视为操作成功。404 分支也会移除本地条目，因此制造了错误的成功记录。

**修复要求：** 操作返回明确结果，例如 `applied / unchanged / stale / failed / aborted`，具体命名由实现决定。只有确认本次写入实际生效才记录“已合并”；别人处理、目标不存在和状态刷新应采用对应反馈。结果绑定课程和页面请求作用域，课程切换清空本页记录，迟到结果不能写入另一课程。网络响应不确定时先核实，不自动重放破坏性操作。

**验收：** 上述双客户端 404 场景不出现已合并记录；正常 200 生效才记成功；幂等 `changed=false`、409、网络失败、卸载、课程切换和迟到响应均有明确行为。课程切换属于代码路径推导出的回归要求，本次没有把它宣称为浏览器已复现缺陷。

“本次已处理”仍是页面内存反馈，不把它包装成持久审计日志；后者另行实施。

### F4 P2 合并后草稿刷新失败仍显示无提示的旧预览

**位置：** `src/frontend/src/composables/useReview.ts:381`，尤其 `draft !== null` 才更新 `draftGraph` 的分支。

**复现：** 页面成功加载后，让下一次草稿图 GET 网络失败，审核队列 GET 正常；执行一次成功合并。实测合并返回 200，图请求失败 1 次，下一条仍显示合并预览，没有“无法预览”提示，也没有刷新错误提示。

**原因及影响：** 队列已更新，旧图仍保留且缺少失效标记，教师无法知道预览基于旧草稿。原交接虽提到可能沿用旧图，但新规格要求读取失败时说明原因；当前实现未把风险告知用户。

**修复要求：** 明确图数据的当前、过期、不可用状态；刷新失败使旧预览失效，显示原因与重试入口。不能因附属图读取失败把已经成功的合并说成失败。首轮加载失败、刷新失败与迟到请求分别处理。

**验收：** 复现中不再无提示展示旧预览；正确保留已成功操作的反馈；恢复读取后预览更新；上一课程或上一修订的图不会覆盖当前图。

**范围提醒：** 当前已确认规格允许没有小图时继续手动操作。本修复先落实准确降级，不自行改为一律禁止合并。总体设计提出“合并需有效服务端计划、小图可降级”的新规则，待相应接口和规格落实后实施。

### F5 P2 单选框方向键被全局候选导航抢走

**位置：** `src/frontend/src/views/ReviewView.vue:164` 的 `isTyping` 与 `:178` 的方向键分支。

**复现：** 至少两条候选；展开一个右侧还有下一条的候选，将焦点置于“保留”单选框，按 ArrowRight。应切换同组保留对象，实测展开的候选对发生变化。

**条件：** 最后一条向右没有可切换条目时不会触发该分支，因此只在末条试方向键可能误判为正常；向左同理。

**修复要求：** 单选组内方向键保留浏览器原生行为，不参与页面候选导航；其他输入框、下拉框、可编辑区域保持现有保护。分别定义方向键和 M/N 的目标元素规则，避免为修方向键误伤其他控件交互。

**验收：** 第一/中间/末条、左/右方向、单选框焦点及页面空白焦点均覆盖。单选组内只换保留对象，页面导航只在允许的焦点位置换条目。修正原交接“单选框方向键不触发”的未成立描述。

### F6 P2 缺少 similarity 时整页被校验拒绝

**分类：** 新前端声明的兼容能力未落实；不是现有后端随机违反契约。当前后端 DTO 仍要求数字 `similarity`。

**位置：** `src/frontend/src/composables/useReview.ts:147` 的 `isDuplicate`；对照 `ReviewView.vue:125` 的可选展示逻辑及新规格“相似度缺失时页面照常显示”。

**复现：** 对审核队列响应做故障/兼容注入，删除一条候选的 `similarity`。整页显示“服务器返回的审核队列数据异常”，尚未到达 UI 隐藏分数的分支。现有相关测试标题提到缺失，但夹具仍传 `similarity: 0.5`，未覆盖该输入。

**修复要求：** 若落实新规格的可选分数，先协调 DTO/OpenAPI/生成类型/响应校验再补测试；旧数字字段仍兼容。若本任务坚持前端限定范围，则明确把此项登记为待契约任务，不能标记新规格完全通过。不能通过补 0、1 或放弃整个响应校验伪装兼容。

**验收：** 在完成契约调整的版本中，真实省略字段时其他栏目与候选正常显示、分数不显示；非法值按契约处理，不能呈现 NaN%。未知 reason 与缺失 similarity 分开测试。未知 reason 在现有数字分数响应中已能回退原文显示。
