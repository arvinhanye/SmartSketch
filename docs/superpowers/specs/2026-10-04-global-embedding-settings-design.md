## 1. 用户目标与已确认范围

目标：启动 SmartSketch 后，在网页填写向量 API，而不是手工把向量 Key 写入 `.env`；配置成功后教师发布和学生检索使用同一个向量空间。

用户已确认：全站一份向量配置，不做每位教师/每门课程各自的向量空间；教师和学生的生成模型仍在原「模型 API 设置」分别选择，不由部署者统一调控。

建议默认方案：增加独立的「向量服务设置」页和首次配置引导；只给部署者修改权限，不创建管理员日常调控、审批或模型分配层。页面填写基址、API Key、模型、维度；有保存、明确计费提示的测试连接、配置状态和错误提示。基础设施/加密根密钥仍由启动流程管理，向量 API Key 可经网页加密入库。

## 2. 为何不只是新增表单

现有实现有以下约束：

- ADR-081：向量为系统级在线服务，Key 从环境读取；个人生成 API 与之独立。
- config.py 在 online 模式下要求基址、Key、模型完整；start-demo.sh --personal 也有同样启动检查。
- API lifespan 和 worker 在启动时校验向量空间；graph_migrations.main 在启动迁移时初始化空间并建立向量索引。
- embedding_space_state 记录模型/维度；缓存、草稿和发布副本向量都与空间绑定。
- API/worker 为不同进程，不能只修改 API 内存配置。向量装配还供发布、问答、离线脚本使用。
- 身份只有 teacher/student，没有现成的全站设置管理员。所有教师都能改全站配置会影响别人的检索和费用，因此需单独限定配置所有者。

因此本提案同步处理网页入口、受控配置接口、加密持久化、缺配置时启动、双进程配置读取、旧环境兼容和既有向量保护。

## 3. 两种配置入口实现路线

| 路线 | 结果 | 选择 |
| --- | --- | --- |
| 网页表单写 `.env` 后要求重启 | API 与 worker 依赖进程环境；首次缺配置仍打不开网页；服务器文件权限与部署方式耦合 | 不选 |
| 网页配置加密存 SQLite，API/worker 按版本读取；保留完整环境配置作旧部署兼容 | 满足先启动再配置，不改用户生成 API；有明确激活与空间一致性门禁 | 建议 |

不做每用户向量、自动重新向量化、本地模型推理、供应商切换器或自动轮换。这些不是当前已确认范围。

## 4. 权限：部署者配置，不新增日常管理员层

建议采用「首次领取配置所有权」：

1. 正式启动脚本生成一个独立的随机初始化码；保存在本机被忽略的私有文件，权限0600。它不是模型 Key，不出现在普通日志、URL、命令参数或前端持久存储中。部署者从该本机文件取得并在网页输入；文件路径由启动提示说明。
2. 用户需先登录教师账号，并提交初始化码，才可首次领取全站配置所有权。不是“第一个登录者自动成为配置者”，也不是按用户名硬编码特权。
3. SQLite 原子绑定 owner_user_id。两人并发领取只成功一个；绑定后其他教师即使知道初始码也不再领取。学生不获修改/测试权限。
4. 后续设置读取、保存、连接测试都要求当前登录用户等于已绑定所有者；后端回查账号状态，不依赖 JWT role 或前端隐藏按钮授权。
5. 普通用户只看向量是否就绪的状态提示，不取得 Key、初始化码、完整配置或账单操作权限。

所有者账号不承担课程审批或其他用户生成模型管理。所有权转交/重置不开放网页自助操作，本轮不提供“清除后重新抢占”路径；后续如需转交，另走本机维护流程。

**本节为待确认的权限提案**：使用一次性本机初始化码，是为了保护全站密钥与费用，不要求部署者手改 API Key 到环境文件。

## 5. 启动和使用闭环

正式网页配置模式：

1. scripts/start.sh 自动准备本机基础配置、登录签名/凭据根密钥、初始化码和数据库迁移。
2. 缺少向量 API 时，API、网页和 worker 进程仍能启动；状态为 not_configured。登录、个人生成 API 设置、课程列表/创建和已有图谱浏览可用。
3. 不初始化假向量空间，不创建临时演示向量索引，不回退 fake/demo。worker 保持健康心跳，尚未就绪时不领取新的业务任务。
4. 页面对未完成向量初始化显示引导；上传抽取、发布和课程问答入口在此模式下需向量就绪，服务端也检查并返回明确配置错误，避免创建永远排队的任务。
5. 部署者领取所有权、填写并保存。保存不隐式调用付费模型；先完成本地验证、加密保存与本机 Neo4j 向量索引就绪检查。首次初始化状态为 initializing，只有 SQLite 空间记录与 Neo4j 索引一致后才进入 ready。
6. 部署者主动点击测试连接时，先看计费提示、确认后才发一次短文本向量请求；测试不写业务图谱，也不发送课程正文。
7. ready 后教师上传→图谱审核/修改→发布，学生使用自己的生成模型问答；发布和问题检索共用全站向量配置。
8. 重启仍从加密配置读取；网页仅显示已设置提示/脱敏提示，不回显原 Key。

状态与错误：not_configured、initializing、ready、unavailable；缺配置返回409 EMBEDDING_CONFIG_REQUIRED，激活中/加密不可读/索引不可用返回503 EMBEDDING_CONFIG_UNAVAILABLE。保存后无需重启全套服务，下一次业务操作读取新配置版本。在途操作使用操作开始时的不可变配置快照。

## 6. 全局配置持久化与进程一致性

- 增加一个全局配置单例：owner_user_id、base_url、model、dimensions、key_ciphertext/nonce、key_hint、revision、激活状态、最近测试的脱敏结果与时间。根密钥仍来自 MODEL_CREDENTIAL_KEY。
- 复用现有 AES-GCM 机制但使用独立的全局向量配置关联数据域；与用户生成 Key 的密文不可互换。仓储只处理密文。
- API、worker、发布/问答和适用的维护脚本共用同一个配置解析服务。每次操作按 revision 取得配置快照，不修改共享 Settings 对象，不通过全局环境变量热改。
- 客户端/缓存按空间和配置 revision 隔离；Key 替换后下一操作刷新客户端。失败不把旧客户端静默复用为新配置。
- 首次激活分为“保留目标版本→幂等创建/核验索引→CAS 标记 ready”。不跨 Neo4j DDL 等待长持 SQLite 写事务；初始化中无业务写入。激活失败保留明确失败状态和可重试版本，原 ready 配置不被失败保存替换。
- 初始化期间进程退出后，可由同一所有者重试幂等激活；不新增付费请求、不自动改变空间、不删旧索引或向量。

SQLite 迁移预计为当前018之后的019（实施前再次检查编号）；无 Neo4j 业务模型破坏性迁移。

## 7. 既有空间与旧配置保护

为了避免“同名模型来自不同服务但向量不一致”，锁定范围包括基址、模型与维度，而非只锁维度：

- 新库第一次成功激活前可调整目标；首次成功启用/已有空间记录后，网页只允许同一基址/模型/维度下替换 API Key。保存不自动清库，不偷偷重算。
- 空间字段更改返回409 EMBEDDING_SPACE_LOCKED，明确提示需按 V12 离线重新向量化或建立新检查环境。本轮不新增网页换模型/重新向量化入口。
- 既有数据库/发布版本永远不由此功能清空、转换、覆盖；旧空间与新配置不匹配时停止向量相关业务操作，保留诊断/设置入口。
- 完整且有效的旧 EMBEDDING_* 环境配置仍可作为兼容来源运行；加密数据库配置存在时优先使用它，并显示来源。首次认领不能改写原环境值或静默复制旧 Key 入库；网页保存时由所有者重新输入 Key。
- 新增明确的配置来源模式：原默认 env 模式维持“缺在线配置即拒绝启动”的旧语义；正式启动入口启用 web 模式，允许 not_configured 但不是 demo。已有完整 env 配置在 web 模式中作为上述兼容回退。
- fake/demo 门禁模式维持既有行为，不出现全局设置业务影响；个人生成 Key/任务快照与“关闭思考”功能均不改。

这意味着首次填错模型且已激活后，也不靠网页直接换空间；可先保存草稿/测试表单参数再激活。界面需在首次保存激活前明确提示锁定边界。

## 8. 提案接口与前端范围

审批后先写 OpenAPI/DTO/规格，再实现；本节为接口候选，不是已存在的接口。

| 接口 | 作用 | 权限/行为 |
| --- | --- | --- |
| GET /api/v1/system/embedding-status | 全站就绪状态和当前用户能否设置 | 已登录用户；无密钥/初始化码/完整配置 |
| POST /api/v1/system/embedding-config/claim | 首次凭初始化码绑定配置者 | 已登录教师+初始化码；已绑定后拒绝其他领取 |
| GET /api/v1/system/embedding-config | 配置视图与锁定状态 | 仅配置者；只返回 key_hint/has_key，不返回明文或密文 |
| PUT /api/v1/system/embedding-config | 保存/激活或替换Key | 仅配置者；expected_revision 乐观并发；表单校验与空间锁定先于修改 |
| POST /api/v1/system/embedding-config/test | 测试当前或未保存表单 | 仅配置者，明确付费确认，限流，一次请求，不保存表单/改业务图谱 |

前端沿用页面→组合式状态→API 客户端分层。新增「向量服务设置」页、部署初始化引导、全站就绪提示；原个人模型页明确“生成模型由你选择，向量由部署者配置”。普通学生没有改配置入口，但可看见不就绪的说明。

测试连接显示成功、实际模型/维度、耗时或脱敏错误；维度不符即失败，不把成功 HTTP 状态视为向量正确。原 Key 输入框不显示已有真实值，Key 不写 localStorage、URL 或控制台。

## 9. 出站、费用和日志

- 网页填写的地址按现有受控模型端点策略做校验、DNS 检查和请求时IP钉住；默认阻断回环/内网/链路本地与不合规重定向。隔离门禁只用已有本机假供应商测试开关，production不放开该开关。
- 未授权/参数不合规的请求不解密Key、不出站。错误不回显输入值、供应商响应正文或凭据；普通日志只含配置版本、状态、耗时与次数。
- 真实测试须有显式计费确认，限流建议沿用5次/60秒语义；不在保存、页面加载、状态刷新、重启时自动发测试请求。
- 每次向量测试沿现有先记账后请求规则：purpose=embedding，course_id使用保留的系统命名空间 `system:embedding-config`，request_id独立、user_id为配置者，输入为固定短测试文本；不创建假课程、不算入生成模型预算。usage 未返回保留null，不填0。
- 账本预写失败则不出站；401/预算拒绝立即结束，不自动重试；UI只显示脱敏分类。Key轮换不触发重新向量化或隐式计费。
- 本设计和实施门禁不使用真实Key、业务库、课程正文、共享Neo4j。任何真实生成/向量试跑先由用户另定预算；旧台账844451/900000与向量12005不变。
