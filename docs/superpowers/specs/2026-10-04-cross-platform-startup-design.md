## 1. 已确认目标与范围

用户确认先做“双击入口＋安装向导＋Docker”：新用户不复制启动命令、不安装宿主 Python/Node、不手动编辑 .env；首次填写必要配置后启动，以后双击进入浏览器。优先参赛交付，保留现有教师抽取→审核→发布、学生学习→提问闭环。

本期包含：Mac/Windows 入口、浏览器首次配置向导、本机服务编排、首个教师创建、重复启动、停止、脱敏诊断、固定版本发行包。Docker Desktop 是唯一需用户预先安装的运行依赖；首次下载还需要网络。安装器不代替用户处理 Docker 许可、系统授权、WSL/虚拟化设置或重启。

本期不包含：原生桌面窗口、桌面安装器、托盘、自动更新、开机自启、无 Docker 运行、局域网/公网部署、演示模式切换、全局向量业务设置页、自动接管旧工作区的数据。此前全局向量网页配置计划保持 CANCELLED_BY_USER；ADR-080/081 存储规则不变。

设计阶段交付只有规格、任务登记、方向决策、集成说明与 Codex 交接。用户已确认本文，当前编写实施计划；启动代码实施仍需计划获批并确定执行方式。

## 2. 已核对的基础与差距

1. docker-compose.yml 已有 app profile：neo4j→migrate→api/worker→web；SQLite 与资料共享 app-data 本机命名卷，web 不注入密钥，服务有重启策略。
2. scripts/start.sh 转交 Bash 开发流程，依赖宿主 Python/npm；不是 Windows 原生入口。当前 scripts 中没有 cmd/ps1 启动包装。
3. 后端镜像已有业务模块、迁移、契约与提示词，但未包含 scripts/manage-accounts.py；新增容器内引导命令须复用账号服务，而非假设现有 Compose 自动创建教师。
4. 身份规格与 auth API 确认学生已有自助注册；manage-accounts.py 文件头“没有注册端点”的旧注释已过时，不据此改变产品。教师创建仍走本机受控工具，不新增教师公开注册端点。
5. 当前开发 Compose 的 Neo4j 数据绑定仓库目录；发行模式需要独立、稳定的命名卷，避免解压目录变化丢失实例关联。
6. 现有 /health 只代表 API 可响应，不代表整套依赖或真实 API 可用；不能用它单独宣布就绪。
7. 尚无本设计的启动器、向导、预构建发行镜像或 Mac/Windows 实机证据。

## 3. 组件与接口边界

### 3.1 轻量共用启动核心

建议新增小型 Go 命令行启动核心（非桌面 GUI），发行包附编译好的程序；用户不安装 Go。原因：只有 Docker 的主机无法直接执行 Python 共用脚本，单一可执行程序可以复用配置、HTTP 向导、实例锁和就绪判定，减少 Bash/PowerShell 两套业务逻辑漂移。Go 是开发/构建依赖，本轮不安装；这项技术选择已随本文确认，仍未实施。

启动核心的职责：定位本机配置、管理单实例、运行内置向导、调用 Docker CLI、校验结果、打开浏览器、诊断脱敏。调用进程用参数数组，不把表单或路径拼成 shell；只支持固定子命令与服务名单。Docker 返回详情先分类/脱敏，再进入界面或日志。

分平台包装只负责定位发行目录/正确架构的启动核心、显示前置故障和启动核心；Mac 的 .command 保留执行位，Windows 的 .cmd 处理路径引号和 UTF-8，必要时使用系统 PowerShell 完成用户权限检查。避免要求 Git Bash、宿主 WSL 命令行开发环境或全局放宽脚本策略。核心发现 Docker CLI 时兼顾 PATH 和官方安装位置，不依赖用户手工修改 PATH。

### 3.2 安装/控制向导

启动核心提供独立于业务 API 的短期 HTTP 页面，仅监听 127.0.0.1 的空闲端口；API 尚未启动时也能配置。页面资源随发行包自带，不引入外部 CDN。提供安装配置、分阶段进度、打开软件、停止服务、脱敏诊断。

控制服务随启动核心存在；终端窗口关闭后控制页显示连接断开，容器业务服务继续运行。再次双击重开控制服务并恢复状态。界面明确“关闭窗口不等于停止服务”；停止按钮只停止本安装实例。

接口是启动器内部协议，不加入 src/contracts 的业务 API：读取阶段/可用操作、提交首次配置、启动、停止、获取已脱敏诊断。每项执行后返回结构化结果及中文提示；错误不包含请求正文或原始 stderr。实施时为内部消息写类型与协议测试。

安全要求：随机不少于 32 字节会话令牌，经浏览器 URL fragment 引导并在首次交换后移除；日志不记录完整打开地址。状态和操作均认证；写请求检查 Host、Origin、令牌和 JSON 类型；不开放跨域，不接受 GET 写操作，不把令牌/密钥存 localStorage/sessionStorage。页面表单完成后清空密钥输入，按会话失效处理泄露风险。只服务发行包内固定静态资源，无任意文件读取、命令执行、镜像/路径输入接口。

### 3.3 发行编排与账号引导

新增发行专用 Compose 清单，复用既有服务、同源 Nginx 代理与 SSE 配置；保持开发 docker-compose.yml/scripts/start.sh 的用途，不影响测量环境。

发行清单只引用固定版本/摘要的预构建镜像；不在普通用户机器安装依赖或编译源码，不使用漂移 latest。已有后端/前端 Dockerfile 是镜像构建基础，但镜像构建、分发权限、amd64/arm64 可运行性仍需单独验证。镜像分发走 GitHub 仓库关联的 GHCR；公开发行包应可匿名拉取，否则发行验收不通过。镜像推送与 GitHub 发布需要实施时明确授权，本轮仅本地文档。

Neo4j、API、worker、web 与迁移共用唯一安装项目名，数据卷以该安装 ID 固定命名。发行模式不对宿主暴露 Neo4j HTTP/Bolt；仅 web 绑定本机回环端口。API/worker 使用同一机器同一 SQLite 卷，避免云盘/网络盘。

新增一次性容器内账号引导命令，复用 services.auth 的用户名、口令规则及密码哈希，且只对新空安装库创建首个教师。密码通过 stdin 传入，不进入命令参数、容器环境或持久初始化文件。创建与核验在事务内；重入时保持已存在账号，不改口令、不补建别的教师。已有库不自动运行首次建号。

## 4. 配置、存储与安装状态

### 4.1 文件归属

- Mac：~/Library/Application Support/SmartSketch/。
- Windows：%LOCALAPPDATA%\SmartSketch\。
- 路径由系统用户目录确定，不依赖当前工作目录；发行包可放在含空格/中文的路径。
- 本机 .env、安装标识、状态文件和脱敏日志在上述目录；业务数据在安装 ID 对应的 Docker 命名卷，升级发行文件不改变项目名/卷名。
- Unix 私有目录权限 0700、.env 0600；Windows 设置为当前用户与必要系统主体的访问权限并核验继承。如果权限保护失败则停止保存，不声称密钥已安全落盘。
- 状态文件不保存任何密钥、密码、令牌或课程正文；记录安装 ID、发行版本、选择的网页端口、阶段及成功引导后的教师 ID/用户名即可。
- .env 依旧只是环境配置，后端不从启动器数据库读取配置；不引入全局模型设置数据库表/业务配置 API。

### 4.2 首次配置

表单要求：向量 API 地址、Key、模型、维度；首个教师用户名、口令与确认口令。默认可提供一个经过验证的供应商配置预设，模型/维度须显示可确认，不把预设等同于联网验证。

生成 LLM_MODE=personal、EMBEDDING_MODE=online、APP_ENV=production；向量地址禁止用户信息和凭据查询参数，按现有出站规则拒绝不合规地址。个人生成模型 Key 不在安装向导填写；教师/学生登录后用现有“模型 API 设置”。

首次自动生成强 Neo4j 口令、JWT 签名密钥与符合 ADR-080 格式的加密根密钥；后续启动绝不重新生成这些值。系统使用明确的现有配置默认项，不盲目复制 .env.example 的 fake 模式/示例口令。迁移与应用使用同一环境文件与镜像版本。

写入采用临时文件、权限检查、同步落盘、原子替换；序列化遵守 Docker Compose .env 规则，测试美元符、井号、引号、反斜杠、CRLF，禁止值中的换行/NUL。既有文件不当作 shell 脚本执行；重复键、非法键或无法无损读取的值应报配置错误，不静默取第一个。

安装状态区分 NEW、CONFIGURED、INITIALIZING、READY、STOPPED、ERROR。配置与状态在同一实例锁保护下更新；只有全部服务检查通过才写 READY。中途失败保留已有配置/卷；重试复用原密码和实例 ID。仅 .env 存在不足以判定安装成功。

### 4.3 既有环境边界

只自动复用本启动器管理的已有安装；本期不自动导入或迁移当前开发工作区的 .env、SQLite、Neo4j 数据。第一次运行须说明“创建独立的新安装，不包含旧开发环境课程”。现有开发入口仍可继续使用原数据。

发现不完整状态、已有未知卷、配置缺失但数据卷存在时，展示恢复指引并停止初始化；不生成新密码、不以新空库掩盖旧数据。配置丢失的恢复依赖原配置备份，启动器不自动重置数据库口令或加密根密钥。

已记录向量空间的模型/维度锁定，禁止直接改写后启动；重新向量化仍按既有 V12 独立操作。首次安装完成后不开放向量 Key 持续设置页；必要更换沿用受控环境配置与重启。这样与撤销的业务设置功能清楚分离。

## 5. 启动、停止、失败与回滚

首次流程：

1. 检查发行文件/系统架构/Docker CLI 与 Compose；Docker 未运行时可尝试打开 Docker Desktop，显示等待/手工启动入口，超时停止，不修改系统设置。
2. 在写入配置前获取本实例互斥锁；竞争双击时打开已有向导。锁包含随机实例标识并核验进程，不能只凭一个过期 PID 文件宣称运行。
3. 获取用户配置→本地格式校验→安全保存→拉取固定镜像。初次拉取显示独立进度/取消；取消保留 CONFIGURED，可重试。
4. 使用唯一 project-name/清单/绝对 env-file 运行本安装 Neo4j并等待真实健康检查。
5. 执行一次性 SQLite/Neo4j迁移，检查退出码；初始化向量空间及索引所需的既有 F03 门禁同样执行。新库不进行真实向量请求。
6. 执行新安装教师引导；进程重启且尚未成功时让用户重新输入密码，不持久保存明文。
7. 启动 API/worker/web；检查 Neo4j healthy、迁移成功、API 可响应且当前 schema/空间匹配、worker 心跳健康、经 web 的登录页/API 同源代理可达。不能只用 docker up 退出码或 /health。
8. 成功后写 READY、显示实际网站地址并打开浏览器；个人生成 API 未配置属于正常引导状态，不是部署失败。

控制页面与业务网站端口分别管理。首次端口冲突时提供空闲端口供用户确认；已有安装端口冲突先解释，再明确确认后只改变该实例 web 端口与 WEB_ORIGIN。不得终止占用端口的其他进程。状态变化需确认实际端口映射，以绑定失败为最终判据，避免检查/绑定竞态。

重启流程先查看本安装健康状态；健康则直接打开；停止则启动；不健康则定位具体服务，呈现重试/诊断。正常启动不自动拉取新版本或更新迁移。检测待迁移/版本变化时先停止本实例 API/worker，等待任务安全退出与租约门禁，备份后再由用户确认升级；不强杀任务后绕过迁移校验。

停止操作只使用本安装 project-name 和固定服务清单，优先正常 stop，保留全部卷；不调用全局停止、不执行 down -v、volume prune、system prune。关闭 Docker 仍使软件停止；不是长期云端部署。停止过程中任务遵守既有租约/宽限期，不改变任务状态机。

失败包括环境缺失、镜像下载、非法配置、权限、端口、迁移、空间不匹配、建号和服务健康失败；分别返回中文原因及下一步，保留脱敏日志路径。超时有明确截止和取消操作；不无限等待或循环重启。就绪检查总等待上限 180 秒，镜像拉取单独显示且可取消；超时阈值需要低配置实机验证。

首次无旧数据的失败：保留卷/配置并可重试，用户明确确认后才清理该未完成实例。已有数据升级：SQLite 用现有离线备份机制，Neo4j 在本实例停机后完整备份卷，核验备份可读；备份未完成禁止迁移。数据迁移后的回滚须恢复匹配的 SQLite、Neo4j、配置与镜像整组备份，禁止仅降级代码假装回滚。控制操作不得接触原工作区或测量库。

## 6. 安全、费用与发布

本地格式/环境/健康检查不调用真实生成或在线向量；默认不提供自动联网 API 测试。页面明确“格式检查通过不代表供应商连接/额度已验证”；后续首次业务请求费用按原有预算与个人配置规则发生。自动启动也不自动上传资料、发布课程或发问。

诊断只记录版本、平台/架构、阶段、服务状态、退出码、允许展示的错误分类和耗时；不收集 env 内容、docker inspect 全量、原始 stderr、课程正文、账号口令、模型 Key 或令牌。诊断导出应先本地预览，不自动上传。测试用诱饵密钥验证无泄露。

发行支持目标：macOS 的 Docker 官方支持版本范围，arm64 与 amd64；Windows 11 x64 + Docker Desktop WSL 2 Linux containers。Windows ARM/Windows Server/无虚拟化及其他替代 Docker 引擎不在首版承诺中。每个标为支持的平台需实机证据；编译成功不能代替双击/首次安装测试。

Go 二进制与 .command 执行位、Windows .cmd 路径/编码、macOS下载来源提示均需要发行测试。未签名产物可能有系统提示，应在说明中披露；本期不承诺零权限提示，不引导关闭 Gatekeeper/SmartScreen。固定镜像摘要与发行包 SHA-256 进入发行清单，构建产物不进源码 Git。第一次镜像发布若权限未批准则保持发行未完成，不回退“让普通用户编译源码”。

## 2026-10-05 收尾复审后的内部协议澄清

- URL fragment 只是一次性引导值。进程控制文件中的 reopen capability 与引导值分别随机生成，页面 token / 已消耗 fragment 都没有重新生成会话的权限；业务 API 不变。
- 固定文件组（.env、发行 compose / manifest、卷映射、安装状态）采用私有写前日志。启动器读配置前完成校验与重放，状态最后发布；中断不重新生成密钥。未知或被外部改写的组保持错误，既有数据不覆盖。
- 暂存恢复失败可继续检查／启动；原安装未切换前仍保留。切换需二次确认，已切换的 generation 登记已消费；再次恢复同一快照须重新解包到新的卷，不复用已发生新写入的活跃卷。
