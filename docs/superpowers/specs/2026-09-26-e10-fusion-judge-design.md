# E10 重复裁决与定义归并设计（待签收）

- 日期：2026-09-26
- 范围：E10；E09、E04 已合入 `main@5072a48`
- 目的：让教师获得可解释、可追溯的疑似重复知识点处理结果，避免错误裁决覆盖原定义。
- 成功标准：裁决有结论与理由；归并定义只基于输入证据且列出出处；非同义、坏输出或预算拒绝时两点与两份原定义保持独立，并生成待审核原因。

## 已确认的边界

1. E10 不内置 `auto_merge` / `review` 阈值。D-08 的初始取值继续待评测签收，延续 E09 的调用方显式传值设计。
2. E10 只处理调用方给出的一对候选及其来源证据，不负责 E08 名称候选与 E09 向量候选合流，也不查库、生成实体 ID、写 Neo4j 或决定自动合并层级。E12 负责候选编排、有效任务集合 V 过滤、调用结果缓存与写入衔接。
3. E10 产出**提案**，不直接修改草稿。教师加锁节点的保护由 E12/F13 写入环节落实；E10 保留供该环节判断的原节点 ID 与来源。

## 方案比较

| 方案 | 优点 | 代价 / 结论 |
| --- | --- | --- |
| **A：独立裁决服务（采用）** | 输入/输出可单测，E08/E09 与模型调用解耦；E12 可统一实施可见性、缓存和写入规则 | E12 需显式组装候选与证据 |
| B：在 E10 合流并裁决 | 调用方看似简单 | E10 需依赖 E08/E09 阈值、草稿可见性与候选优先级，职责扩张 |
| C：由 E12 内联提示词和裁决 | 少一个服务模块 | 无法独立验证模型输出及失败路径，提示词版本和缓存元数据容易散落 |

## 输入、输出与依赖

- 输入：同一 `course_id` 的 `left_id < right_id` 候选对；两侧名称、类型、原始定义；每段可用证据的稳定 `source_id`、原文片段与文档/修订/块位置。无来源、跨课程、重复 ID、空名称等由边界校验拒绝，不能拿缺失证据进行归并。
- 模型依赖：注入现有 `ModelClient`（通常为 E04 策略绑定后的客户端）和 E01 `PromptLibrary`；E10 不自行配置供应商、预算、重试或日志原文。
- 输出：结构化 `FusionDecision`，携带候选 ID、`same` 结论、非空理由、结果状态（可归并提案 / 保持独立待审核）、可机读原因、原两侧来源、可选统一定义与其 `source_ids`，以及提示词用途/版本/摘要、实际模型 ID 和调用次数供 E12 缓存及审计。输出是服务内部类型，不新增 API wire DTO。
- 原实体不变：任何失败结果都不改写输入，不生成合并实体 ID；E12 根据分层与锁状态决定后续动作。

## 调用顺序与证据约束

1. 固定使用 `judge_duplicate@2`，提示词载入两侧名称、定义及带 `source_id` 的证据。要求 JSON 布尔 `same`、非空 `reason`、非空且仅来自输入的 `source_ids`。`same=false` 时结束，返回独立待审核；不请求定义归并。
2. 仅 `same=true` 且结构合规时调用 `summarize_definition@2`。要求非空 `definition` 与非空 `source_ids`；每个 ID 必须属于输入，两侧来源均可追溯。提示词明确只使用给定原文，资料中的指令一律当数据。
3. E10 对结构、类型、长度、来源 ID 做确定性校验；引用不存在的来源、空理由/定义、截断或无效 JSON 都属于坏输出。来源 ID 校验是**可追溯性校验**，不能数学地证明改写内容的每一句都受原文支持；统一定义仍作为可审核提案，不把模型输出视为已获教师确认的事实。
4. 两个提示词正文升级时同步更新 `prompts/MANIFEST.md` 的版本、变量和 sha256。`ModelRequest` 明确 `response_format=json` 与输出上限；原文不进入日志、错误消息或对象 `repr`。

## 失败与重跑

- 坏 JSON、结构/来源校验失败或截断：按现有模型接入约定在同一模型最多修复一次；仍失败则保留原候选及定义，返回可机读待审核原因。第一阶段失败时不进入第二阶段；第二阶段失败也不得保留半成品合并。
- 非同义裁决：保留独立，并送教师审核，理由可见。预算拒绝：不发额外请求，保留独立并送审。
- 模型整体不可用、存储级故障：不伪装成普通“不重复”；向 E12 传递阶段级临时故障，按 `specs/task-processing.md` §8.3 重排。
- E10 无持久缓存。E12 使用课程、候选对、两段证据内容摘要、提示词用途/版本/正文摘要及实际模型版本形成缓存身份；证据变化必须失效。此项是对 §8.4 既有缓存键的收紧，实施前同步更新该规格。失败/待审核结果是否缓存由 E12 按其检查点语义确定，不在 E10 写存储。
