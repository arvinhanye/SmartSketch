# 教师个人向量模型设计

用户已明确：教师 API 设置增加向量模型及维度选择，按该教师创建的课程生效；学生无新增设置。

## 输入、输出与边界

输入：供应商对应 HTTPS OpenAI 兼容地址、密钥、模型、1..4096 维度。输出：独立教师向量配置的读取、测试、模型目录和保存；教师设置页沿用通用模型表单风格。密钥使用现有 AES-GCM，绑定 embedding:user_id 的独立域，不回传、不缓存到前端。

## 课程空间

新增教师配置表，课程通过 courses.teacher_id 解析配置；未配置的课程继续使用系统默认。教师空间包含教师 ID、服务地址/模型摘要及维度，避免不同供应商/教师向量混用。学生问答取课程教师向量配置，同时仍使用学生自己的对话 API。发布/回滚取课程配置，不改学生界面。

保存变更地址/模型/维度前：获取教师及其课程写锁并续约；生成目标空间的新属性/索引，重建该教师课程所有 Chunk、草稿和已发布 KnowledgePoint 向量，核对数量/维度/库存及锁令牌；SQLite 事务内切换教师配置和对应版本 embedding_space。旧属性不删除。任何失败不切换旧配置；全系统离线 reembed 遇到个人向量配置时拒绝，避免错误全局覆盖。新课程并发创建导致课程集合变化时保存返回可重试冲突。

## 验收

教师/学生权限、密钥隔离、不同教师/课程空间、旧配置回退、维度响应校验、保存与测试分离、课程发布和问答使用课程向量、前端状态/账号切换/窄屏；合同生成/type-check/build/basic及相关后端测试。本地运行应用需要备份并执行新增 SQLite 迁移，保留已有系统默认配置。
