## 3. 全局约束（继承试点并追加）

- 业务与契约不变：不新增接口字段、数据模型、业务流程；任何需要新数据的设计一律按「现有数据能算出什么」降级，做不到就标「第二批外」。
- 不新增依赖、不引入 UI/图标库；图标继续用 `AppIcon`（内联 SVG，按需追加）。
- 不用整体 `opacity` 淡化；动效只动 `transform`/`opacity`，统一 `cubic-bezier(0.2, 0, 0, 1)`，不用 `transition: all`；`prefers-reduced-motion` 下关闭位移/缩放/循环动画。
- 保留每个页面既有 `data-test` 钩子；重做导致钩子必须变更时，在该阶段计划里列出并同步测试与端到端，不静默删除。
- 测试：先写失败测试再实现；既有断言只在「样式/结构/文案随设计变化」处更新并写明原因，不放宽、不删除。
- 颜色按**页面实际渲染色**验收：文字 ≥4.5:1、必要图形与控件边界 ≥3:1；装饰分隔线不承担识别。
- 侧栏/抽屉：宽屏并置（占比规则同试点 35% / 窄屏 90%），**不用内部滚动条、不用 `overflow: hidden` 裁切**，长内容整页滚动；抽屉打开焦点进标题、Esc 关闭并把焦点还给开关、关闭时 `inert`（写 `true`/`undefined`，不写 `false`）。
- 全站旧样式（`styles.css` 的 `button`、`section`、`.app-main > section` 等）特异性低但无处不在：新样式一律带作用域前缀，并显式覆盖旧规则（试点已验证做法）。
- 问答页是暗色页，**不得继承 `--gw-*`**（规格 §3.1）。
- 登录凭据问题仍未解决：不得猜测或重置账号；需要真实实例的验收由用户提供环境，没有就写「未做」。
- 用户可见文案变化单独列出，并同步测试与端到端（试点「未开始」→「未学习」是先例）。

## 4. 跨页面的设计体系

### 4.1 表面与 tokens（决定）

- **暗色表面 `data-surface="dark"`**：背景 `--ss-bg`，面板 `--ss-panel`，抬升 `--ss-raised`；用于外壳与问答页。
- **浅色内容表面 `.light-surface`**：把试点 `--gw-*` 的作用域选择器由 `.graph-workspace` 扩成 `.graph-workspace, .light-surface`，数值不变；用于课程列表/主页、设置、资料、审核、成员、教师图谱外围。`graph-theme.test.ts` 的 token 比对扩展到新作用域，保证两处一致。
- 内容页的外观：暗色外壳之下是一块圆角 10px、`--gw-panel` 底的「内容页」（外留 12px，与试点工作区同款），不是整页白底，也不是暗底上散落的白卡片。
- 不改全局 `--color-*`，直到 R7 收口。

### 4.2 通用组件与类（先在一页里写，第二页要用时再抽；R1 只做下表标「R1」的）

| 件 | 形态 | 批次 |
| --- | --- | --- |
| `PageSheet`（`.light-surface` 内容页容器，含滚动与最大宽度 `min(1120px, 100%)`） | 组件 | R1 |
| `PageHeader`（标题 20px/28px、副标题、右侧操作槽、面包屑由外壳提供不在此重复） | 组件 | R1 |
| `StatePanel`（加载骨架 / 空 / 错误（带重试）/ 未授权），`role` 与 `aria-busy` 规范化 | 组件，试点 `gw-state-wrap` 抽象而来 | R1 |
| `ui-btn`（primary `#5B5BD6` 白字、secondary 边框、ghost、danger ghost；40px 高、6px 圆角） | CSS 类 | R1 |
| `ui-field`（标签 + 输入 + 说明 + 错误；输入边界 `--gw-edge` ≥3:1；焦点环 2px `--gw-accent`） | CSS 类 | R1（设置页首个使用，R3 完善） |
| `ui-row`（整行可点列表行，min-height 56px，hover/选中/焦点态） | CSS 类 | R2 |

| 骨架屏（900ms 低幅循环，固定占位，减少动效下静止） | CSS 类 | R1 |

原则：不预先建组件库；`ui.css` 全部选择器带 `.light-surface` 或 `[data-surface='dark']` 前缀。

### 4.3 外壳通用化规则（R1）

- 条件：已登录且路由不是登录/注册 → 暗色外壳（顶栏 + 64px 图标栏，<1024px 抽屉）；未登录页（登录、注册）保持现状。
- 图标栏项（按课程内角色，沿用 L15 规则，不猜测权限）：我的课程 / 课程概览 / 学生：知识图谱与学习路径、课程问答 / 教师：教学资料、图谱编辑、审核队列、成员 / 模型 API 设置（带「未配置」徽标）。
- 面包屑：`我的课程 / <课程名> / <当前页>`；课程名取自课程详情（读取失败时回退「课程」）；最后一项 `aria-current="page"`。
- 保留的全局能力：演示模式提示（`mode-demo`）、`nav-model-settings` 与 `nav-model-settings-pending`、路由提示条（`app-notice`，可关闭，`role="alert"`）、`app-user`、`app-sign-out`（试点已移到顶栏）。
- 旧 `.app-sidebar` 的标记在 R1 删除；旧 CSS 保留到 R7 一并清理，避免中途回滚困难。
- 页面容器：`app-main` 的内容页 `PageSheet` 填满剩余视口，内部滚动由页面自己决定（图谱类页面整块工作区、表单类页面整页滚动）。

### 4.4 文案与可访问性（全站统一）

- 页面标题 `h2`，区域 `h3`；状态消息 `role="status"`，错误 `role="alert"`；不靠颜色传达状态（徽标带文字、错误带图标 + 文字）。
- 文案原则（回应「AI 味」反馈）：直接、具体、不夸张；动作按钮用动词（「新建课程」「上传资料」）；空态说明原因 + 下一步；不使用「赋能」「智能」等营销词。文案改动集中在各页「文案表」，不散落。
- 触屏点击区 ≥44×44；焦点环 2px、offset 2px（暗底 `#B1ACFF`，浅底 `#5145CD`）。

## R2 课程列表与课程主页（`CoursesView`）

**现状（已核实）**：`CoursesView` 同时渲染三块——「当前课程」（课程内身份、状态、下一步、**六条以段落形式堆叠的入口链接**：图谱/编辑图谱/审核/资料/问答/成员）、「课程列表」（卡片：名称链接 + 身份/状态/知识点数 + 简介）、「创建课程」表单（教师）。入口多、层级平、纯文本链接——正是用户反馈的「入口多、信息层级松散、部分文字无样式」。

**默认决定（沿用 Linear 行式列表）**
- **课程列表**（`/teacher`、`/student`、以及课程主页下方的「其他课程」）：整行可点的行式列表，行内：课程名（15px/500）+ 一行简介（次级色，省略）｜身份徽标（教师/学生）｜状态徽标（草稿/已发布 vN，文字 + 颜色）｜知识点数｜右侧箭头。行高 ≥56px；hover/选中（`aria-current="page"`）/焦点态齐全。空态：说明原因 + 下一步（教师：「新建第一门课程」按钮；学生：沿用「把用户名告诉任课教师」的说明并加一个「复制用户名」按钮——**不新增接口**，只复制已有用户名）。加载骨架三行；错误带重试；越权提示条保留。
- **创建课程**（教师）：列表右上「新建课程」主按钮，展开为页内面板（不是模态，避免焦点陷阱改动）：名称、简介（计数提示）、「创建」「取消」；成功后面板收起、列表顶部出现并高亮新课程、`role="status"` 提示。表单校验、`COURSE_NAME_MAX`/`COURSE_DESCRIPTION_MAX` 不变。

## 8. 给接手者的第一步

1. 读本文 §1–§5、`docs/handoffs/codex-ui-graph-pilot-01.md`（试点实际做了什么与遗留）、PR #321 状态；确认基线命令（试点后前端 57 个文件 / 1144 条，type-check 与 build 通过）。

3. 每个阶段重复：认领 → 代码级计划 → TDD 执行 → 验收 → 交接 → 用户确认 → 下一阶段。
