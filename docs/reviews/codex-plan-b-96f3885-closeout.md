### E2：汇总脚本时间筛选与预算混算（已定位，待修测量工具）

忽略目录中的 `summary.json` 为 calls=18、billed=29007。完整关联是 **19 调用 = 9 生成 + 10 向量**，两类 usage 相加为 29010，而预算中的生成单列为 28951。

原因：起点 `2026-10-03T18:16:00Z` 与 `created_at=2026-10-03T18:16:00.314Z` 直接字符串比较，带毫秒的同秒记录排在无毫秒的 Z 前，被 `created_at >= :started_at` 漏掉。漏掉的是额外尝试的 3 token 向量。脚本又把向量和生成一起放进 billed。**正式报告已经按完整数据单列统计，正式 28951/59 总数正确，遗漏没有改变此次未越线结论。** 原始摘要不适合作为未来硬止损账本。

下一轮测量工具先修：按请求 ID 关联，时间用 `julianday`（或统一格式）比较；生成与向量分组；usage 未知显式登记；错误编号兼容 details。参考只读 SQL：

```sql
SELECT request_id, purpose, status, max_output_tokens,
       usage_input, usage_output, created_at, latency_ms
FROM model_calls
WHERE julianday(created_at) >= julianday('2026-10-03T18:16:00Z')
ORDER BY created_at;
```

范围要包含显式 ended_at 或固定 request_id 集，避免后续调用污染历史轮次。
