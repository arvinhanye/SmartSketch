## 问题

### A08-R01 P2：`no_graph`（已发布空图）与 A04 V3 冲突，属不可达状态

- **位置**：`specs/learning-path.md:61`（空态表第 3 行）、`:94`（LP-11）。
- **触发条件**：A04 V3 发布校验表明确 `empty_graph`——发布集合没有任何知识点 → 409 `PUBLISH_BLOCKED`。回滚只能指向已提交版本，而已提交版本都过了这道校验。所以正常路径下不存在“发布版 `V=∅`”。
- **影响**：规格把一个不可达状态当成与 `all_mastered` 并列的正常业务态，B12 会为它加 wire 判别值，前端会渲染“这门课没有知识点”。真出现 `V=∅` 只可能是快照/物化损坏，应走完整性错误。LP-11 要求测试的三态中有一态无法经真实发布流程构造。交接称“S2 §6.4.7 与 A04 V1/V2/V8 逐项比对一致”“三空态 PASS”，漏看了 V3。
- **最小修复**：把已提交版本 `V=∅` 归入第 2 行“发布版图损坏”，并注明依据 A04 V3 `empty_graph`；LP-11 改为“未发布 → 404 `GRAPH_NOT_PUBLISHED`；全掌握 → `all_mastered`；`V=∅` 的损坏快照 → 完整性错误”。若产品确实要第三种“无图”态，须先说明它指什么，并由产品签收。

### A08-R02 P2：中心度分母写成 `2(N−1)`，在 DAG 中恒 ≤ 0.5；该拆分也不在待签收清单

- **位置**：`specs/learning-path.md:41`。
- **触发条件**：去重后的 DAG 里，任意两点之间至多一条边（有两条就成二元环），所以 `in+out ≤ N−1`，`centrality ≤ 0.5`。参考脚本：星形中心点在 N=2/3/5/10/50 时都等于 0.5；3000 个随机 DAG 的最大值也是 0.5。
- **影响**：`i(k)` 实际值域是 `[0, 0.75]`。中心度在重要度里的有效占比约为 1/3，而不是规格写的“0.5×/0.5×”。稀疏图里度数除以 `N−1` 本身已接近 0（N=100、度为 3 → 0.015），中心度几乎不起作用。另外“0.5/0.5 拆分”和“度中心度”都是 Codex 自己的提案，S2 只写了“重要度与图中心度加权”，但 §7 没有把它们列为待签收。
- **最小修复**：改为 `(in+out)/(N−1)`（DAG 去重后 ≤ 1），或按本版本最大度数归一化并写明零分母；把拆分比例和中心度定义加入 §7 待签收。回归用例：星形中心点的中心度 = 1。

### A08-R03 P2：合并时不转移进度，与合并契约语义冲突，会让学生进度倒退；属产品决定，却已写成定论

- **位置**：`specs/learning-path.md:75`、`:92`（LP-9）。
- **触发条件**：候选真源 `kp/merge` 规定“被合并节点的名称并入 `aliases`，关系与来源取并集后迁移到主节点”，也就是认定两者是同一概念。按 A08 的规则：学生已掌握 `a`，教师把 `a` 合并进 `b` 并发布后，`a` 进入 dormant，`b` 仍为 unknown；`a` 原有的后继边已经迁到 `b`，这些后继从“可学”变成“未解锁”。
- **影响**：只要教师清理重复节点，学生看到的进度就倒退，而且这是合并功能的主要用途。S2 没有给出这项规则，§7 也没有把它列为待签收，不符合“人工决策保留未签收标记”。另外，合并后主节点是沿用某个现有 `kp_id` 还是另起新 ID，仍未定义（DAG-8 把合并结果写作新符号 `M`）。如果另起新 ID，两边的进度都会 dormant。
- **最小修复**：把合并规则移入 §7，列出两个选项：（1）保守 dormant，接受倒退；（2）按合并谱系取来源节点状态的最大值，需要 F10/B11 在版本中记录谱系。同时注明依赖“合并后主节点 ID 规则”。LP-9 在签收前标为条件性验收。

### A08-R04 P2：“进度中出现非本版本 kp_id → 拒绝”与 §5 投影冲突，而且按给定输入无法实现

- **位置**：`specs/learning-path.md:9`（函数签名）、`:19`、`:67`、`:95`（LP-12）。
- **触发条件**：纯函数是 `recommend(graph, progress, weights, limit)`，`graph` 只包含单一绑定版本。§1 要求：进度中出现非本版本的 kp_id 就拒绝，但“历史已删除节点”除外，应投影为 dormant。只看单一版本，无法区分“历史上存在过、后来删掉”和“从未存在”。
- **影响**：实现者只能二选一。一种是凡是不在 V 中的都拒绝：教师删掉任一节点并重新发布后，掌握过该节点的学生每次请求推荐都报错，而且自己无法修复，因为 §5 禁止写已删除节点。另一种是全部投影，那么“拒绝”这条规则就是死规则，LP-12 的外课 ID 断言写不出来。
- **最小修复**：写明前置条件：调用方传入已投影的 `M ⊆ V`，纯函数只校验图本身。把“从未在本课程任何已提交版本中出现过的 kp_id”放到仓储层检测，按本课程全部 `committed` 版本 kp_id 的并集判断，并规定处置方式（建议记录告警并忽略，不阻断学生请求）。LP-12 拆成图错误和进度脏数据两条。

### A08-R05 P3：章节秩忽略层级；“跨章节取最早”的前提与现有模型不符

- **位置**：`specs/learning-path.md:42`、`:101`。
- **触发条件**：A04 快照的章节带 `parent_id`（`specs/teacher-review-publish.md:151`），A08 却按 `(order, chapter_id)` 扁平排序。如果 `order` 是同级内序号（树结构通常如此），1.1 和 2.1 的 `order` 都是 1，会穿插排序。另外，A04 快照和候选真源的知识点都只有单个可空 `chapter_id`，不存在“跨章节知识点”。
- **最小修复**：秩定义为按 `parent_id` 构成的树做前序遍历，每层按 `(order, chapter_id)` 排序；或者明确 `order` 是课程内全局序号，并交 B11/F 组约束。删去或改写“跨章节取最早”这一待签收项。补一条嵌套章节的验收用例。

### A08-R06 P3：学生读路径上的图损坏借用教师 409 错误码

- **位置**：`specs/learning-path.md:19`、`:60`。
- **问题**：`CYCLE_DETECTED` 是教师编辑成环时返回的 409（`specs/course-knowledge-graph.md:30`、候选真源 `createRelation`）。已提交版本有环，属于服务端数据完整性故障；A04 V9 对当前版本损坏的处理是 5xx。给学生返回 409 加环路，暗示客户端能修正，还暴露了内部结构。
- **最小修复**：学生路径统一返回 5xx 完整性错误，附诊断 ID；环路和悬空端点写入日志/告警，不放在学生响应里。

### A08-R07 P3：权重“可除一次”是可选步骤，同分又用浮点精确相等，结果不唯一

- **位置**：`specs/learning-path.md:15`、`:51`。
- **问题**：“不隐式归一化”和“计算前可按总和除一次”并列，读起来互相矛盾。而且除不除由实现自选，两个都合规的实现在 1e-16 量级上会得到不同的 `score`，同分判定和排序就可能不同。
- **最小修复**：二选一写死（建议不除，校验通过即原样使用），并规定求和顺序为 `u, i, c, e`，保证确定性。

### A08-R08 P3：进度接口的细节缺口
