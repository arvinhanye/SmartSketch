# 双击启动与本机安装

本指南适用于包含 `release-manifest.json`、`compose.release.yaml`、`bin` 与双击入口的完整预览包。镜像按清单中的真实摘要拉取，不要求普通用户编译源码。本地交付包及各平台的实际验收结果以同版本交付报告为准；源码目录不是安装包，预览包也不代表技术冻结。

## 第一次使用

1. 安装并打开 Docker Desktop；Windows 11 x64 使用 WSL2/Linux 容器。Mac 按芯片下载对应包。
2. 获取交付的完整包并核对同目录 SHA256SUMS；Mac 双击 `.tar.gz` 解压，Windows 将 `.zip` 全部解压。保留整个文件夹，不要单独移动入口或 bin。
3. Mac 双击 start-macos.command；Windows 双击 start-windows.cmd。保持 Docker 运行，不要求安装 Python、Node 或 Go。
4. 浏览器安装向导里的「服务商预设」默认选「阿里云百炼」，已预填 API 地址、模型名 `text-embedding-v4` 和维度 1024，你只需要填 Key；用其他服务商时选「其他服务商」，自行填写 HTTPS `/v1` 地址、精确模型名、输出维度及 Key。维度按供应商说明填写，默认 1024 不是对所有模型通用，建立索引后不能更改。这里填的是**系统默认**向量服务（学生使用的也是它）；教师登录后可以在「模型 API 设置」里为自己的课程单独设置向量服务。每一项下面都有填写说明。填写首位教师用户名（3–32 位英文字母/数字/`_.-`，英文字母自动转小写）、至少 8 位密码并确认；网站端口默认 8080。随机数据库口令、JWT 与个人模型凭据加密根密钥自动生成，无需自己创建 .env。
5. 点击“保存配置并启动”。首次会下载后端、前端和 Neo4j 镜像，耗时取决于网络；出现明确错误时处理后点击重试。等待“打开软件”可用，再点击进入登录页。用向导里刚设置的教师账号登录，不是演示账号。教师/学生在网站的“模型 API 设置”填写各自生成模型 API；学生通过登录页的注册入口创建学生账号，再由教师加入课程。

这是新独立安装，不包含旧开发环境课程。配置只做格式检查，未验证供应商连接或额度，不自动调用收费 API。现有开发环境的 .env 不会自动导入，也不会覆盖它。登录后看到空课程列表属于正常的新安装状态。

## 生命周期

- 配置保存在 Mac ~/Library/Application Support/SmartSketch 或 Windows %LOCALAPPDATA%\SmartSketch；数据在安装 ID 的命名卷。
- 再次双击复用原安装；关闭终端/控制页不会停止 Docker 中的业务服务。
- 仅“停止服务”停止本安装，保留卷和原密钥；不会终止占用端口的其他进程。
- 缺 Docker/配置损坏时，按提示处理后重试；不自动降级到演示模式。
- 已保存配置后端口冲突，在控制页面“更换网站端口”输入1024–65535的空闲端口，明确确认只停止本安装后保存，再点击启动；课程、账号和密钥保留，不关闭其他程序。
- 不要删 .env 或手工更换 MODEL_CREDENTIAL_KEY / Neo4j 口令；丢失时需要原配置备份。

## 升级与恢复保护

没有自动更新。版本不一致时启动器停在升级保护，不执行迁移。

受控核心提供先确认停机、租约检查、整组卷归档、配置/发行清单与摘要核对；恢复只写暂存卷。恢复先完成暂存服务的探测，再要求第二次确认切换，原卷保留。只降级镜像、只还原 SQLite 或重新生成密钥都不构成完整恢复。

备份包含密钥与课程资料，应留在本机私有目录，不上传 GitHub 或当作诊断附件。真实Docker合成安装的停启、双安装隔离、整组备份/重复恢复测试结果见本轮报告；这不是用户真实业务库恢复的签收。真实业务数据恢复及三平台正式包操作尚待验收，不能把合成场景当作生产恢复保证。任何真实升级/恢复请先保留原安装和完整快照，并等待对应版本的验收说明。

## 平台边界

Mac Intel、Mac Apple Silicon、Windows 11 x64 分别选 `darwin-amd64`、`darwin-arm64`、`windows-amd64` 包；Windows ARM 不在本期范围。源码跨编译与多架构镜像构建不等同于实机通过。匿名镜像拉取、入口/浏览器实测、Finder 手工双击、中文路径、Docker 未运行与中断恢复均以对应验收报告为准，不互相替代。

预览程序尚未进行 Apple 签名/公证或 Windows 代码签名，系统可能显示来源提示。如果被系统拦截，先确认下载来源与摘要，按系统提供的受控打开流程处理；不要全局关闭 Gatekeeper 或 SmartScreen。若有问题，提供页面的固定错误阶段或脱敏诊断，不要发送 .env、Key、密码或备份。

## Mac下载后出现Killed:9 / 退出码137

已发生的2026-10-05故障：下载二进制SHA与发行附件一致，但Intel启动器未签名且有下载隔离标记；syspolicyd明确记录Gatekeeper拒绝PID44020。该实例不是Docker/API故障。137本身不证明所有场景都由Gatekeeper造成，仍须结合日志，可能还涉及内存/其他终止原因。

当前预览包未经过Developer ID签名及Apple公证。若你已核对来源和SHA，愿意自己承担信任未验证程序的风险，可在尝试打开后到“系统设置→隐私与安全性”审阅仅针对smartsketch-launcher的“仍要打开”提示并自己确认，再重开入口。Apple说明该按钮通常在尝试后约1小时内可用：https://support.apple.com/guide/mac-help/mh40617/mac 。这不是关闭全局Gatekeeper，不由启动器自动代操作。系统若明确提示恶意程序，请停止使用并反馈；若没有对应提示，也不要删隔离属性，请发固定错误/截图。

入口已补137的说明和保留退出码；这只修复诊断信息，不等于已解决下载信任。完整发行还需证书签名、公证及真实下载后的启动验收，ad-hoc签名不代替这项要求。用户现有下载包不因源码修改自动更新，本轮未更改下载文件、Release附件、系统设置、原API配置或数据库。


## 2026-10-06 启动器热修复：旧安装卡在创建教师账户
