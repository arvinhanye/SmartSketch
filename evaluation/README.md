## 3. 标注集格式（`fixtures/*.json`）

```json
{
  "schema_version": 1,
  "dataset_id": "synthetic-ds-ch3",
  "is_final_benchmark": false,
  "note": "……最终基准课程与章节由 D-01 决定……",
  "license": "项目自编，可随仓库分发",
  "course": {"id": "synthetic-ds", "name": "数据结构（自编示例）", "chapter": "第3章 栈与队列"},
  "documents": [{"id": "doc-ch3", "filename": "ch3-stack-queue.md", "format": "md", "text": "……"}],
  "gold": {
    "entities": [{"id": "g-e02", "name": "栈", "aliases": ["堆栈", "stack"], "type": "concept",
                  "document_id": "doc-ch3", "evidence": "<原文连续子串>"}],
    "relations": [{"id": "g-r01", "from": "g-e01", "to": "g-e02", "type": "PREREQUISITE",
                   "document_id": "doc-ch3", "evidence": "<原文连续子串>"}]
  }
}
```

| 字段 | 约束 |
| --- | --- |
| `schema_version` | 整数，当前为 `1`；字段含义变化时加 1 |
| `is_final_benchmark` | `false` 表示开发集；报告必须据此注明「开发集结果，非最终判定」 |
| `note` | 可选，人读说明，脚本不解析 |
| `documents[].format` | `pdf`/`docx`/`txt`/`md` 之一；`text` 为资料全文（开发集直接内嵌） |
| 实体 `id` | `g-eNN`，集内唯一 |
| 实体 `type` | E05 `ENTITY_TYPES` 五类之一（见 3.1） |
| 实体 `aliases` | 同一知识点的其他写法（英文名、简称、编号如「例 3-1」）；可为空列表。不同实体的名称与别名在归一化后不得相同 |
| 关系 `id` | `g-rNN`，集内唯一 |
| 关系 `from`/`to` | 必须是本集实体 ID，不得自环 |
| 关系 `type` | E11 `RELATION_TYPES` 四类之一（见 3.2） |
| `evidence` | 必须是 `document_id` 所指文档 `text` 的**精确连续子串**（不做空白或标点归一），与 E05/E11 的证据规则一致 |
| `PREREQUISITE` | 金标内必须无环 |

### 3.1 实体类型定义

| 类型 | 含义 | 本集示例 |
| --- | --- | --- |
| `concept` | 术语、数据结构、特性等被定义或解释的概念 | 栈、循环队列、后进先出 |
| `theorem` | 可陈述、可证明的定理、性质、判定条件 | 出栈序列计数定理、循环队列判空与判满性质 |
| `formula` | 可直接计算的数学表达式或公式 | 卡特兰数公式、循环队列元素个数公式 |
| `method` | 算法、基本操作、处理过程 | 入栈、中缀转后缀算法、括号匹配算法 |
| `example` | 例题、具体实例、案例 | 表达式求值示例（例 3-4） |

### 3.2 关系类型与方向

| 类型 | 方向语义 | 本集示例 |
| --- | --- | --- |
| `CONTAINS` | `from` 包含 `to`：上位概念 → 下位实现/组成部分/基本操作 | 栈 → 顺序栈；队列 → 入队 |
| `PREREQUISITE` | `from` 是 `to` 的先修：学 `to` 之前要先掌握 `from` | 取模运算 → 循环队列 |
| `EXAMPLE_OF` | `from` 是 `to` 的例子（`from` 通常为 `example` 类） | 括号匹配示例 → 括号匹配算法 |
| `RELATED_TO` | **无方向**：对照、互补、解决关系等其他相关 | 先进先出 — 后进先出 |

### 3.3 标注约定

1. 金标收录资料中**被定义、陈述或演示**的知识点；只顺带提到而未讲解的词（本集如「单链表」「广度优先遍历」「作业调度」「组合数」）不收。因此模型抽出这些词在自动指标中计为假阳性，但人工判定时可能判为正确——自动指标是开发信号，赛题硬指标以人工判定为准（第 6 节）。
2. 名称取资料中最规范的写法；例题统一命名为「……示例」，编号写入别名。
3. `PREREQUISITE` 只在资料明确表达先后依赖时标注，同句并列提及不标（可标 `RELATED_TO`）。
4. 本集有意包含以下边界用例：
   - 先修表述命中 E11 `PREREQUISITE_CUES` 的前置边（「需要先掌握」「先理解」「前提」「以……为基础」）；
   - 一条表述为「基于」的前置边 `g-r03`（栈 → 括号匹配算法）：「基于」**不在** E11 当前清单内，E11 会按 `prerequisite_without_cue` 丢弃，用于观测该清单造成的召回损失；
   - 例题指向定理/公式/算法的 `EXAMPLE_OF` 边，含同一例题指向两个目标（例 3-2、例 3-4）；
   - 上位概念到组成部分、基本操作与实现方式的 `CONTAINS` 边；
   - `RELATED_TO` 无向边；
   - 证据用指代（「该算法」）或位于例题正文内、不重复写出端点全名的情况。

### 3.4 修改标注集

改正文或金标后必须重新校验：JSON 可解析；实体/关系 ID 唯一；关系端点存在且非自环；每条 `evidence` 是所属文档 `text` 的子串；实体 ≥ 30 且覆盖五类；关系 ≥ 25 且覆盖四类；名称/别名归一化后不跨实体冲突；`PREREQUISITE` 无环。校验命令与结果记入交接文件。

`predictions.json`（一次抽取运行的产物，取自该章资料处理到 `awaiting_review` 后的草稿，即融合去重之后）：

```json
{"run_id": "...", "dataset_id": "synthetic-ds-ch3", "model": {"id": "...", "is_fake": true},
 "prompt_versions": {"extract_entities": 2, "extract_relations": 2},
 "entities": [{"id": "p-e1", "name": "栈", "type": "concept", "source": "ai"}],
 "relations": [{"id": "p-r1", "from": "p-e1", "to": "p-e2", "type": "PREREQUISITE", "source": "ai"}]}
```

`judgments.json`（人工判定，对应一次运行）：

```json
{"run_id": "...", "judge": "<判定人>", "seed": 20260926,
 "entities": {"p-e1": "correct", "p-e2": "incorrect"},
 "relations": {"p-r1": "correct"},
 "notes": {"p-e2": "名称截断"}}
```

- `dataset_id` 须与标注集一致；`judgments.run_id` 须与 `predictions.run_id` 一致，否则拒绝计算。
- `model.is_fake` 为真时，报告照常计算，但结论一律写「fake 模型，不能用于证明达标」。
- 判定值只允许 `correct`、`incorrect`；判错项应在 `notes` 写明依据哪条标准（第 6.3 节编号）。
- 各指标只统计 `source = "ai"` 的条目；其他来源的条目不参与任何指标，报告列出其数量。
- 实体 `id`、关系 `id` 在各自列表内唯一；关系端点须指向本文件中的实体 ID，否则该关系按第 5.2 节计为假阳性。

## 5. 自动指标（对照金标）

### 5.1 实体匹配

1. **名称归一化**：`NFKC` → `casefold` → 删除全部空白字符（Python `\s`）。
2. 预测实体与金标实体匹配，当且仅当预测名称归一化后等于金标名称或其任一别名的归一化结果。
3. **一对一**：按预测在输入中的顺序逐条处理；每个金标实体至多被匹配一次。命中已被匹配金标的后续预测计为**重复假阳性**（`duplicate`）；一个金标都不命中的计为**多余假阳性**（`spurious`）。
4. 报告两个变体：
   - **名称级**（不看类型）：只按第 2 条匹配；
   - **带类型**：名称匹配且预测 `type` 与金标 `type` 相等才算匹配；按同样的一对一规则独立走一遍。
5. 关系端点映射使用**名称级**匹配的结果，且只映射一对一匹配成功的预测实体；重复假阳性与多余假阳性实体不映射。

### 5.2 关系匹配

1. 预测关系的 `from`、`to` 经 5.1 第 5 条映射为金标实体 ID；任一端点无法映射（未匹配、重复、或不在预测实体中）→ 该关系为假阳性。
2. 映射后若金标含 `(from, to, type)` 则为正确；`RELATED_TO` 不看方向（金标中 `A—B` 与 `B—A` 等价）。方向相反的 `CONTAINS`/`PREREQUISITE`/`EXAMPLE_OF` 判错。
3. 一对一：每条金标关系至多被匹配一次，重复命中计为重复假阳性。

### 5.3 指标

- `precision = TP / 预测数`（预测数含重复与多余假阳性），`recall = 被匹配的金标数 / 金标数`，`F1 = 2PR / (P + R)`。
- 同时给出**总体**与**分组**结果：
  - 实体按五类分组（带类型变体）：第 t 组的预测为 `type = t` 的预测，金标为 `type = t` 的金标；
  - 关系按四类分组：`CONTAINS`、`PREREQUISITE`、`RELATED_TO`、`EXAMPLE_OF` **四类始终全部列出**，某类为空也列出。
- **空分母给 `null`**：预测数为 0 时 `precision = null`；金标数为 0 时 `recall = null`；`precision` 或 `recall` 为 `null` 时 `F1 = null`；两者均为 0 时 `F1 = 0`。不得输出 0 代替 `null`，也不得输出 `NaN`。
- 数值用 Python `round(x, 4)` 保留 4 位小数；计数保持整数。
- 同一输入重复运行结果必须逐字节一致（固定排序、固定种子，不写入时间戳或其他随机量）。

## 6. 赛题硬指标（验收 7）

两项硬指标**都**必须达标，本章才算满足赛题「技术要求与指标（一）」。

### 6.1 实体数

- `entity_count` = 预测中 `source = "ai"` 的实体数（融合去重之后的草稿节点）。
- 阈值：`entity_count ≥ 20`；**恰为 20 视为达标**。

### 6.2 人工抽样准确率

- 实体与关系**分别**计算（D-15），各自 `准确率 = 判为 correct 的抽样项数 / 抽样项数`。
- 阈值：各自 `≥ 70%`；**恰为 70% 视为达标**；两项都达标才算通过。比较用整数形式 `correct × 10 ≥ 7 × n`，避免浮点误差。
- 抽样项中有任一项缺少判定时，该项指标写「判定不完整」，不得给出达标结论。
- **抽样方法**（实体、关系各自独立）：
  1. 总体 = `source = "ai"` 的预测条目；
  2. 按条目 `id` 字符串升序排序；
  3. 总体 ≤ 100 时**全量检查**；否则用 `random.Random(seed).sample(sorted_ids, 100)` 抽 100 条，实体、关系**各自新建**一个 `Random(seed)` 实例；
  4. 默认 `seed = 20260926`；判定文件中的 `seed` 须与抽样所用种子一致；
  5. 报告写明种子、总体数、样本量或「全量检查」，并**逐条列出**被抽样的项（ID、名称/两端名称与类型）与判定结果、判错理由。

### 6.3 判定标准

判定人逐条对照资料原文判断，每条须满足下列**全部**标准才判 `correct`。判 `incorrect` 时在 `notes` 写明违反的编号。

**实体**

- E1 是本章资料中实际讲授的知识点（被定义、陈述或演示），不是泛泛词语（如「元素」「操作」「问题」）、章节标题噪声或资料中没有的外部知识。只被顺带提到的术语，若在本章上下文中确实是有意义的知识点，可判对并在 `notes` 注明。
- E2 名称完整准确：未被截断、未把多个知识点拼成一个、未把整句当名称。
- E3 类型符合第 3.1 节定义；两类皆可时（如「性质」归 `theorem`）按第 3.1 节判定，定义未覆盖的两可情况判对并注明。
- E4 若系统给出定义或证据，其内容与该知识点一致、不张冠李戴。
- E5 不是融合遗漏的重复：与样本中另一条已判对的实体为同一知识点时，按 ID 顺序后出现的判错。

**关系**

- R1 两端都指向本章真实知识点（端点实体满足 E1、E2）。
- R2 类型符合第 3.2 节定义。
- R3 方向正确：`CONTAINS` 上位 → 下位；`PREREQUISITE` 先修 → 后学；`EXAMPLE_OF` 例子 → 被例示者；`RELATED_TO` 不看方向。
- R4 `PREREQUISITE` 表达真实的学习先后依赖，而不只是同句出现或并列提及。
- R5 证据是资料原文，并确实陈述了这条关系（结合上下文的指代可以接受，如「该算法」、例题正文）；证据与这条关系无关则判错。
- R6 不与样本中另一条已判对的关系重复（`RELATED_TO` 不分方向）。

### 6.4 判定对象与材料隔离

- **只统计真实模型的输出**。`model.is_fake = true` 的运行只用于验证流程，结果**永远不能**用来证明达标。
- 真实模型运行在 D-02 签收后执行；产生付费调用前须另行取得用户确认。
- 提示词、先修表述清单、融合阈值（D-08）等只在**开发集**上迭代，不用最终判定材料 `synthetic.json`（D-01 / ADR-026）；**阈值不在测试集上调**。最终判定材料只用于判定。
- 若提示词迭代所用材料与最终判定材料相同，报告必须**显式注明**「迭代材料与判定材料相同」。
- 判定标准、种子和样本量在看到判定结果前确定，之后不得为凑达标而修改。

### 6.5 失败路径与报告内容

- 实体数 < 20，或任一准确率 < 70% 时，报告如实写「**未达标**」并给出差距（例如「实体数 17，差 3 个」「关系准确率 64.00%，差 6.00 个百分点」）。不得通过重抽样、换种子、放宽标准或剔除样本凑数。
- 报告还须列出：错误类型及计数（按 6.3 编号或自动指标的 `duplicate`/`spurious`、方向错误、类型错误等归类）与改进方向；运行的模型 ID、提示词版本、数据集 ID 及其 `is_final_benchmark`。

## 8. 问答指标（待 J06）

问答链路依赖 J06，尚未完成。以下只定义口径，**不建问答标注集**；J06 验收后再补 `fixtures/` 中的问答用例（问题、真值是否被资料覆盖、期望引用）。

- **引用有效率**：答案所附引用中，能在本课程已发布资料中定位到的比例——文档 ID 存在、页码或章节存在、引用片段是该处原文。分母为引用总数，为 0 时给 `null`。
- **引用支持度**：有效引用中，片段确实支持答案对应陈述的比例（人工判定；标准为「只读该片段即可得出该陈述」）。分母为有效引用数，为 0 时给 `null`。
- **未覆盖混淆矩阵**：真值为「资料覆盖 / 资料未覆盖」，系统输出为「作答 / `NOT_COVERED`」，得到 2×2 矩阵：

  | | 系统作答 | 系统 `NOT_COVERED` |
  | --- | --- | --- |
  | 资料覆盖 | 正常作答 | 误拒 |
  | 资料未覆盖 | **臆答**（最严重） | 正确拒答 |

  由此报告 `NOT_COVERED` 的精确率、召回率与臆答率（臆答数 / 资料未覆盖问题数），空分母同样给 `null`。
- 问答阈值同样不在测试集上调，判定对象同样只算真实模型。
