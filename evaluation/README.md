# 评测

归 Data/AI Agent（AGENTS.md §3「评测资产」）。两类评测：**抽取准确率**与**问答质量**。

## 布局

```text
evaluation/
├── README.md              # 本文件
├── extraction/            # 抽取评测脚本：知识点、四类关系、融合消歧
├── qa/                    # 问答评测脚本：来源正确性、NOT_COVERED 判定
├── performance/           # 分阶段耗时实测脚本
└── reports/               # 报告产出目录（内容不入库，见 .gitignore）
```

标注集与问答测试集放在 `datasets/`，不放在本目录——评测脚本与被评测数据分开，换标注集时不必动脚本。

脚本按评测类型分文件，新增评测**新建文件**，不要往已有脚本里堆分支。

## 评什么

| 评测 | 对象 | 关注点 |
| --- | --- | --- |
| 抽取准确率 | 知识点抽取、关系抽取、融合消歧 | 与标注集对比的准确率/召回；四类关系是否混淆；`PREREQUISITE` 是否产生环 |
| 问答质量 | 带出处问答 | 来源是否可定位且确实支持答案；资料未覆盖时是否正确返回 `NOT_COVERED` 而非臆测（ADR-003） |

## 报告

- 产出到 `evaluation/reports/<提示词 id>-v<版本>-<日期>.md`。
- 报告**不入库**：它是可重新生成的产物，且常包含课程原文片段。目录本身用 `.gitkeep` 保留。
- 结论要回填到对应提示词 YAML 的 `changelog.effect`，写实测数字（见 `prompts/README.md`）。

## 抽取准确率：标注规范与指标

本节对应命题企业提交材料的「知识抽取准确率的测试报告」，以及 `specs/course-knowledge-graph.md` 的准确率验收条件。

**标注规范**

- 每门课选 2 章，由 2 名成员**独立标注**，计算 Cohen's Kappa 一致性系数；分歧项由第三人仲裁。
- 知识点匹配先做别名归一（全半角、去空格、去括号内英文缩写）后再判定命中。
- 关系判定以 `specs/` 中四类关系的判定准则为唯一标准，**「仅提到」不算前置**。

**指标**

| 指标 | 定义 |
| --- | --- |
| 知识点 P / R / F1 | 以标注集为标准答案 |
| 关系 P / R | 分 `CONTAINS`/`PREREQUISITE`/`RELATED_TO`/`EXAMPLE_OF` 四类分别统计 |
| 悬空关系率 | 端点不在实体表中的关系占比，应为 0 |
| 环冲突数 | 抽取结果中被环检测拦截的前置边数量 |

**目标**：赛题底线为人工抽样准确率 ≥70%；本方案目标知识点 ≥85%、关系 ≥75%。

**消融实验**（用于证明两阶段抽取的有效性，对应 M3-02）

| 两阶段 | | | |

## 问答评测：测试集构成

测试集每门课 40 题，四类均衡覆盖：

| 类别 | 说明 | 考察点 |
| --- | --- | --- |
| 事实型 | 定义、公式、结论 | 检索命中与引用准确 |
| 关系型 | 「学 X 之前要学什么」「X 与 Y 区别」 | 图谱结构检索 |
| 跨章节 | 答案需合并多章证据 | 混合检索能力 |
| 超纲拒答 | 课程资料覆盖不到的问题 | 是否正确返回 `NOT_COVERED` 而非编造 |

**指标**：回答正确率、引用准确率（引用片段是否真正支撑结论）、拒答正确率、首字与完整响应耗时。

## 性能评测

记录解析、实体抽取、向量化与融合、关系抽取、校验入库各阶段耗时，以及问答首字/完整耗时。
报告必须注明**机器配置与文档字数基准**（基准为单章约 2 万字），否则数据不可比。

## 可比性

同一指标只在**同一份标注集**上跨版本比较。换标注集必须重测基线，并在报告开头写明用的是哪一份、版本是多少——否则「版本—改动—效果」表里的数字没有意义。

## 数据约束

- 标注集与测试集使用开源教材或团队自编讲义，**不放入有版权的真实课程资料**。
- 每份报告在文件头注明所用提示词版本、模型名与温度，确保可复现。
