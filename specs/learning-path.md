## 1. 输入、输出与不变量

推荐核心是无网络/无数据库副作用的纯函数 `recommend(graph, projected_status, weights, limit)`。调用方先按 G07 在请求开始解析一个已提交的 `(course_id, version_id, version)`，然后依 §5 从该学生的课程进度与**绑定版本的合并谱系**得到 `projected_status`；纯函数不查询历史版本，也不判别原始进度行属于哪个课程。`graph` 是该单一发布版本的完整节点、章节和 `PREREQUISITE` 边，不能用 UI 当前筛选出的子图计算。教师草稿、其他课程节点和历史版关系均不进入函数。

| 输入或输出 | 领域含义与约束 |
| --- | --- |
| `V`、`E` | `V` 为该版本所有知识点的唯一 `kp_id` 集；`E ⊆ V×V`，`(a,b)` 表示 `a` 是 `b` 的直接前置。只有 `PREREQUISITE` 参与，其他三类关系不参与。重复边去重；自环、悬空端点、环均为图错误，不静默修复。 |
| `projected_status(k)` | 只含 `V` 中的 ID，取值 `unknown / learning / mastered`；无记录等于 `unknown`。`M = {k∈V | projected_status(k)=mastered}`。`learning` 不满足先修。原始进度按 `(user_id, course_id, kp_id)` 标识，`kp_id` 在版本间稳定；合并继承仅作读时投影。 |
| `weights` | 默认 `(unlock=.35, importance=.25, chapter=.20, ease=.20)`，按此固定顺序。依 ADR-014 修订 1 决定 6，来自环境变量 `RECOMMEND_WEIGHT_UNLOCK`、`RECOMMEND_WEIGHT_IMPORTANCE`、`RECOMMEND_WEIGHT_CHAPTER`、`RECOMMEND_WEIGHT_EASE`：四项都不设时用默认值，四项都设时用所设值，只设一部分则拒绝启动。每项必须为有限、非负实数，和必须在 `1 ± 1e-9` 内且至少一项正数，否则拒绝启动。进程启动时读取一次，全站统一；校验通过后**原样使用，不再除以总和**。不做课程级配置，也不接受学生请求传权重。 |
| 单条推荐 | `kp_id`、`graph_version`、四个原始分量 `u/i/c/e`、四个加权分量、`score`、`unlock_count`、结构化理由事实及一句由事实生成的文字。每个原始分量均在 `[0,1]`，`score` 为四个加权分量之和。 |
| 推荐结果 | `state`、固定版本号、`total_eligible`、稳定排序后的至多 `limit` 条。`limit` 为正整数；I05 默认 10、最大 50，超出拒绝（ADR-014 修订 1 决定 7）。先对**全部**候选计算分量和排序，后截断；不先筛 UI 章节。 |

前置图即使理论上在发布时经过 DAG 检查，推荐服务仍对该版本全图做线性时间校验：重复 ID、自环、悬空端点、环、章节树损坏或非法数值都属于**已提交版完整性故障**。学生读路径统一返回 5xx 完整性错误和诊断 ID，不输出部分推荐或内部节点 ID/环路；服务端日志/告警保留具体 ID 与环路。教师草稿编辑成环时的 409 `CYCLE_DETECTED` 不用于学生读路径。纯函数只接受 `projected_status` 的键集 `⊆ V`；原始进度中的历史、外课或脏 ID 在调用前由 §5 的仓储边界处理，不能让学生请求因历史删除而失败。

## 2. 可学集合与人工越序掌握

令 `Pred(k) = {p | (p,k)∈E}`，`M = {k∈V | projected_status(k)=mastered}`。可学集合严格为：

```text
Eligible(V,E,M) = { k ∈ V \ M | Pred(k) ⊆ M }
```

无前置节点天然可学；只看**直接**前置。多个前置必须全部掌握，`learning` 不算。原始进度行是学生声明的事实；`M` 是从该事实和已签收合并谱系导出的本版本有效集合，不由拓扑排序或推荐服务写回修改。教师后续增删先修边只改变重新计算出的可学集合，不批量重写学生进度。

**人工跳过先修**：MVP 不设 `skipped` 第四种状态，也不把“查看下游节点”当作解锁。学生可手动把任一已发布节点标为 `mastered`，即使它的前置未标掌握；这属于自报的**越序掌握**，保存该节点本身的 `mastered`，不自动标记或豁免任何前置。它可作为其直接后继的已掌握前置，但仍未掌握的其他前置照常阻挡后继。UI 对越序点显示未掌握前置的提示；取消该节点的 `mastered` 后按新 `M` 立即重算。单独的“豁免前置/跳过但不声称掌握”工作流若以后需要，必须先扩展进度契约与产品决定，不可暗中在 `Eligible` 里加例外。

## 3. 四项纯函数评分

所有分量只从当前绑定版本、当前 `M` 和明确参数计算；不能依赖 Neo4j 返回顺序、当前时间或模型生成。`N = |V|`；下表所说的缺失默认值仅用于发布图尚未提供数值属性的兼容场景，发布后这些属性在该版本内不可变。

| 分量 | 精确定义 | 零分母/缺值 |
| --- | --- | --- |
| 实际解锁数 `unlock_count(k)` | 对候选 `k`，计数 `|{v∈V\M : (k,v)∈E 且 Pred(v)\M = {k}}|`。仅算**学完 k 后立即**变为可学的不同直接后继；不算已掌握、还缺其他前置或仅经多跳到达的点。 | 无这样的后继时为 0。 |
| 解锁度 `u(k)` | `unlock_count(k) / max_{x∈Eligible} unlock_count(x)`；分母按本次全部候选算，不按返回前 `limit` 个算。 | 最大值为 0 时所有候选 `u=0`；不把 0/0 当 1。 |
| 重要度 `i(k)` | `0.5 × importance(k) + 0.5 × centrality(k)`。依 ADR-014，`centrality(k) = (in_degree(k)+out_degree(k)) / (N−1)`；只计去重后的前置边，覆盖当前版本全图，与 `M` 无关。 | `N≤1` 时中心度 0；缺 `importance` 时用中性值 0.5（ADR-014 修订 1 决定 5）。明确存在但不在 `[0,1]` 或非有限的值是数据错误。 |
| 章节顺序 `c(k)` | 发布版章节按 `parent_id` 组成树/森林，先按根、再递归按子章节作**前序遍历**，每层按 `(order, chapter_id)` 升序；得到 `C` 个秩 `r=0..C−1`。每个知识点至多引用一个 `chapter_id`，取该章的秩。`C>1` 时 `c=1−r/(C−1)`。 | `C=1` 且节点属于该章时为 1；无章节或节点的 `chapter_id=null` 时为 0。引用不存在的章节、父章节不存在或章节成环是完整性错误，不当作无章节。 |
| 易学度 `e(k)` | `1−difficulty(k)`；难度使用 `[0,1]` 标准化数值，0 最易、1 最难。 | 缺难度时用中性值 0.5；明确存在但非法的值是数据错误。不得从章节位置推断难度。 |

```text
score(k) = w_u × u(k) + w_i × i(k) + w_c × c(k) + w_e × e(k)
```

按 `u → i → c → e` 的固定顺序计算四个加权分量并依次求和；计算和排序均用未舍入值，不在排序前按展示小数位截断。wire 上传未舍入的 double，只有前端展示时舍入；`score` 必须与按 `u → i → c → e` 顺序对 wire 中未舍入加权分量求和的结果逐位相等，不用各分量的展示值重算。`importance`、`difficulty` 的 `[0,1]` 范围已在候选契约 `KnowledgePoint` 和 A04 快照中确立，B12 仍须遵守；属性缺失时的中性值 0.5 已由 ADR-014 修订 1 决定 5 签收。

排序键为 `(-score, chapter_rank, kp_id)`：得分降序；同分时有章节且越早越前，无章节秩视为 `+∞`；仍同分按 `kp_id` 的 UTF-8 字节序升序。仅当未舍入的分数完全相等才走同分键，不用展示精度作比较。所有候选在**本轮开始**均满足前置条件，因此返回列表中的两个候选不可能有先修边；此性质比“排序后再检查前置”更强。

## 4. 理由与空态

理由从与该条响应同源的结构化事实生成，绝不调用 LLM。至少保留 `unlock_count`、章节秩/章名、重要度与中心度、难度及四个加权分量；一句话优先解释**加权贡献最大**的分量，同贡献按 `unlock → importance → chapter → ease`。示例：`完成该点可立即解锁 2 个知识点（解锁度 1.0000）`；若获胜分量为章节，说明实际章序；若全为 0，说明 `当前无可直接解锁的后继；此点的直接前置均已掌握`。理由不能把 `u=1` 误说成“解锁 1 个”，也不能在 `unlock_count=0` 时称其可解锁后继。

| 条件（按判定顺序） | 结果 |
| --- | --- |
| 鉴权失败或尚无发布指针 | 遵守 IAM 的 401/403；尚未发布为 404 `GRAPH_NOT_PUBLISHED`（A04）；不运行推荐函数。 |
| 已提交版图损坏：`V=∅`、环、悬空端点、重复 ID、章节树损坏、非法数值 | 5xx 完整性错误，附诊断 ID；不返回部分推荐。A04 V3 的 `empty_graph` 阻断空图发布，回滚只复制已提交的非空快照，因此 `V=∅` **不是正常 wire 空态**。 |
| `V≠∅` 且 `M=V` | `state=all_mastered`，列表空。 |
| 其他正常情形 | DAG 保证至少一个候选，`state=recommendations`；截断后仍报告完整 `total_eligible`。 |

## 5. 进度跨版本投影与写入

进度真相存 SQLite，按 `(user_id, course_id, kp_id)` 保留，不按整数版本号复制一份。A04 保证同一逻辑点的 `kp_id` 在发布、改名和回滚之间稳定；仅名称变化不改变掌握状态。请求先固定 `(version_id, version)`，然后在同一一致性读取边界取该学生该课程的原始进度、绑定版本 `V` 与版本化合并谱系，**读时**算出 `projected_status: V → MasteryStatus`；纯函数只接收投影结果。删除节点的历史行不进入当前推荐，也不被清理。没有合并时，该投影即原状态在 `V` 上的限制；有合并时按 ADR-014 继承，不可只作集合交集。

仓储层先以已认证 `(user_id, course_id)` 隔离原始进度。若行的 `kp_id` 不在**本课程所有 `committed` 版本**的 ID 并集中，记告警与诊断 ID 后忽略该脏行，不阻断学生读取；这个判定不能只靠单一绑定图完成。已在历史版出现、当前版不存在的 ID 是合法 dormant 行，不告警。请求体中的外课/历史 ID 则按下文写入校验拒绝，不能混同于仓储脏行。

合并谱系以有向 `merged_id → primary_id` 表示，主节点沿用 `primary_id`。链式合并可传递。对绑定版本中的每条谱系链，把来源进度归属到链上**最近的仍在 `V` 中的节点**：来源自身在 `V` 时归自己；来源不在 `V` 时才归其当前可见主节点；若中间节点在 `V` 则先停在中间节点，不越过它归给更远主节点。若整条链均无 `V` 中节点（如 A→B 后 B 被删除而非再合并），来源记录为 dormant，不被任何节点继承。绑定版本谱系须满足每个来源至多对应一个主节点且无环；违反时按 §1 的已提交版完整性错误返回 5xx 与诊断 ID，不输出部分进度或推荐。每个可见节点 `p` 的有效状态，取 `p` 自身记录与归属到它、且**未被覆盖**的来源记录中的最高状态，序为 `unknown < learning < mastered`。继承不写回任何原始进度行；回滚使来源重现时它重新使用自身记录，主节点不再从它继承。

**显式写入覆盖继承**（ADR-014 修订 1 决定 9）：设来源 `m` 在绑定版本（版本号 `n`）中归属到 `p`。从 `n` 起逐个往前检查已提交版本，`m` 连续归属到 `p` 的最早一个版本记为 `k`，`k` 的提交序号记为 `T`。`p` 自身记录的写入序号大于 `T` 时，`m` 被覆盖；否则 `m` 照常参与取最高。回滚使 `m` 重新出现即中断连续，再次合并时从新版本重新起算。写入序号与提交序号取自 SQLite 中同一个单调序列，分别在进度写入事务和版本提交事务内取号；不用客户端时间、`updated_at` 或 `committed_at`。`k` 在读取时计算，可按 `version_id` 缓存，不写入快照。由此，合并生效后学生对 `p` 的任何显式写入（包括 `unknown`）都会覆盖当前归属到 `p` 的全部来源；只有写在该次连续合并起算之前的 `p` 记录，才与来源一起取最高。

`GET /progress` 与成功的 `PUT /progress` 都按各自绑定的发布版本 `V` 返回**每个节点**的进度项，而非只返回有原始行或本次写入的节点；`status` 是与推荐使用同一投影的有效状态。每项另带 `own_status`（该学生在此 `kp_id` 的原始状态，无行则为 `null`）和 `inherited_from[]`（归属到此节点、有原始行且未被覆盖的来源，每项为 `{kp_id, status}`，按 `kp_id` 的 UTF-8 字节序排列；自身记录不列入）。`updated_at` 只表示该节点自身原始行的更新时间，无自身行则为 `null`，不冒充继承来源的时间。以上字段已由 ADR-014 修订 1 决定 8 签收，由 B12 写入契约。主节点的记录写在合并起算之前、又低于来源时，有效值由来源决定，响应表现为 `status` 高于 `own_status`，`inherited_from[]` 中列出该来源；合并生效后再写主节点，则来源被覆盖，`status` 等于 `own_status`，`inherited_from[]` 不再列出它。进度响应与推荐须在相同绑定版本和进度快照上计算；`PUT` 则在提交后按最终绑定版本重新投影并返回。

| 版本变化 | 进度处理 |
| --- | --- |
| 同 `kp_id` 改名、改属性、改先修边 | 原状态保留；排序和可学条件用新版本属性/边重算。 |
| 新增节点 | 无记录等于 `unknown`；不得继承同名旧节点的掌握状态。 |
| 删除节点 | 原进度变为 dormant（不在当前进度/推荐列表，也不计入 `M`），记录保留以供历史版或回滚读取。 |
| 删除后同一 `kp_id` 在回滚/恢复中重现 | 原状态重新可见；因为这是同一个逻辑身份。新建同名但不同 `kp_id` 绝不继承。 |
| 合并 `a→b`，`a` 从当前版消失 | 依 ADR-014，把 `a` 的历史状态**读时继承**到 `b`，与 `b` 自身记录取最高；`b` 自身记录写于本次连续合并起算之后时，`a` 被覆盖（ADR-014 修订 1 决定 9）。不改写两者原始行。若 `a` 重新出现在绑定版本中，则 `a` 用自身记录，`b` 不再从 `a` 继承。 |
| 回滚为新发布版本号 | 先解析新 `version_id`，按该版本节点重新投影；不回滚、不覆盖学生曾写的进度。 |

写入进度只对请求事务所见的**当前已发布版**且其中存在的节点有效；草稿独有、已删除、他课节点拒绝。`PUT /progress` 的请求体是 `ProgressUpdate[]`：先对整批做鉴权、非空/字段与 ID 校验，任一项非法或同批 `kp_id` 重复则**整批拒绝、零写入**；合法批次在一个 SQLite 事务中全写入，同值写入按下文判定；身份只从已认证学生取得，不能信任请求中的 `user_id`。发布指针在写入期间变化时，提交前重新核对版本，若任一目标已不在新发布版则整批拒绝；若全部仍在则按新版本提交并回传新 `graph_version`。读请求中的进度快照与图版本一旦固定，不因途中发布或改标记而混算；后续请求可观察新状态。当前 `GET /progress` 只读当前发布版，无按历史版本查询参数；历史状态保留由仓储层验收，不虚构历史读接口。

**同值写入**（A08S-R01，由 ADR-014 修订 1 决定 9 推导）：写入项的 `status` 等于该节点原始 `status` 时，不能只凭原始值相同就跳过，须在提交时的最终绑定版本上判定这次写入是否还会改变覆盖关系。若当前归属到该节点且未被覆盖的来源为空（没有来源，或自身写入序号已大于全部来源的界 `T`），则为无操作：不取新写入序号、不改 `updated_at`，响应照常按投影返回。否则它是一次显式写入，照常取新写入序号并刷新 `updated_at`，从而覆盖这些来源（决定 9）。由此，同一绑定版本下重放同一请求时，第二次起都是无操作，有效状态、原始行与 `updated_at` 均不变。

## 6. A08 验收矩阵（交后续任务实现）

| ID | 路径 | 必须观察到的结果 |
| --- | --- | --- |
| LP-1 | `M=∅`，A 无前置、B 依赖 A | 仅 A 可学；B 不因 UI 筛选或高重要度提前出现。 |
| LP-2 | C 依赖 A、B；`M={B}`，A 可学 | 学完 A 的 `unlock_count=1`；`M=∅` 时该计数为 0；多跳后继不计。 |
| LP-3 | 所有候选都不能立即解锁其他点 | 所有 `u=0`，无除零；孤立点仍在候选中。 |
| LP-4 | 单节点/单章节/无章节、缺数值属性 | 中心度和章节/难度/重要度按 §3 的零分母与默认规则；数值仍在 `[0,1]`。 |
| LP-5 | 权重环境变量全 0、负数、NaN、总和偏离 1，或四项只设一部分；以及四项都不设 | 前几种情形拒绝启动；四项都不设时用默认值 `.35/.25/.20/.20`；合法权重下四个分量可重建 `score`。 |
| LP-6 | 同分、不同章节或同章不同 ID；`limit=1` | 固定 `u→i→c→e` 加权求和；仅未舍入分数完全相等才用 `(chapter_rank,kp_id)` 打破平局；先全量排序再截断，`total_eligible` 不丢。 |
| LP-7 | 学生越序把 C 标 `mastered`，A/B 仍未掌握 | 只记 C；A/B 仍可学，C 的后继仍按全部直接前置判定；无自动豁免。 |
| LP-8 | 发布 v2 把已掌握 A 改名、删除 B、新增同名 C | A 保持掌握，B dormant，C unknown；B 的原始仓储行仍保留，回滚绑定到含 B 的版本时可重新投影。当前 `GET /progress` 无历史版参数。 |
| LP-9 | A 已掌握、B 未知（B 无记录，或记录写于合并之前），A 并入 B 且原后继迁到 B | B 有效为 mastered，原后继按新前置可学；A/B 原始进度行字节不变。B 的 learning 记录写于合并之前、A 为 mastered 时，B 仍是 mastered；A→B→C 链式合并时 C 继承 A/B 的最高状态；回滚使 A 重现时 A 用自身记录、B 不再从 A 继承，近期写入也不被回滚覆盖。 |
| LP-10 | 推荐已绑定 v1 时 v2 提交 | 本请求的图、进度投影、理由和响应版本均为 v1；下一请求可读 v2。 |
| LP-11 | 未发布、全部掌握、损坏的已提交 `V=∅` 快照 | 分别为 404 `GRAPH_NOT_PUBLISHED`、`state=all_mastered`、5xx 完整性错误与诊断 ID；无 `no_graph` wire 状态。A04 V3 的 `empty_graph` 阻断正常空图发布。 |
| LP-12 | 已提交版有环/悬空端点；原始进度有历史 dormant 行或从未属于本课程的脏 ID；写入夹带外课 ID | 图错误为 5xx 与诊断 ID，具体 ID/环仅入服务端日志；历史行保留并投影排除；脏行告警后忽略而不中断读取；外课写入整批拒绝，均不输出部分排名。 |
| LP-13 | 原始 `unlock_count=2` 且归一化 `u=1` | 理由写“解锁 2 个”，结构事实/分量与评分一致，不用模型生成。 |
| LP-14 | 2～5 点的前置星形 DAG，中心点连接其余所有点 | 中心点 `centrality=1`，每个叶子 `centrality=1/(N−1)`；`N=1` 为 0。 |
| LP-15 | 章节树含根 1 的子 1.1、根 2 的子 2.1，两个子章 `order` 都为 1 | 章节秩按前序为 `1,1.1,2,2.1`，不把同级序号误作全局序号；节点只引用一个章节，`chapter_id=null` 得 `c=0`。 |
| LP-16 | 批量 `PUT /progress` 含一项非法或重复 `kp_id`；以及全合法批次 | 前者零写入；后者单事务全部写入；同值写入按 §5「同值写入」判定，同一绑定版本下重放第二次起为无操作；发布指针变化后的校验覆盖整批。 |
| LP-17 | A 已掌握、B 无进度行；A 并入 B 并发布 | `GET /progress` 返回 V 中每个节点；B 的 `status=mastered` 与同版本推荐一致，`own_status=null`、`updated_at=null`，`inherited_from[]` 指明 A 的 mastered 记录。 |
| LP-18 | 继 LP-17，合并生效后 `PUT /progress` 写 B=`unknown`；另设 B 在合并之前已有 `unknown` 记录 | 前者：写入成功，响应返回 V 中每个节点；B 的 `status=unknown`、`own_status=unknown`，`inherited_from[]` 为空（A 被覆盖），推荐按 B 未掌握计算，A 的原始行不变。后者：合并后 `GET` 返回 B 的 `status=mastered`、`own_status=unknown`，`inherited_from[]` 含 A；接着学生同值 `PUT` B=`unknown`（A08S-R01 回归）→ 这是一次显式写入，取新写入序号，B 的 `status=unknown`，A 被覆盖，`inherited_from[]` 为空；立即重放同一请求 → 无操作，写入序号与 `updated_at` 不变，响应相同。 |
| LP-19 | A→B 后 B 被删除而未再合并 | 链上没有 V 中节点，A/B 原始记录保留为 dormant；当前进度与推荐均不将 A 的状态继承给任何节点。 |
| LP-20 | v1 含 A、B；v2 合并 A→B；学生写 B=`unknown`；v3 回滚到 v1，A 重现；学生写 A=`mastered`；v4 再次合并 A→B；之后学生再写 B=`unknown` | 绑定 v3 时 A、B 各用自身记录。绑定 v4 时，A 的连续归属从 v4 起算，B 的 `unknown` 写于 v4 提交之前，不覆盖 A，所以 B 的 `status=mastered`、`inherited_from[]` 含 A。之后再写 B=`unknown`，A 被覆盖，B 的 `status=unknown`。判定只比较共享序列的序号，与时间戳无关。 |

## 7. 接口与已签收事项

> 本节各项已由 ArvinHan 于 2026-09-23 签收，记为 ADR-014 修订 1（决定 5～10）。

- **B12 接口**（决定 8）：B12 必须先在 ADR-004 的 YAML 真源 `src/contracts/api.v1.yaml` 中定义以下内容，再生成两端类型，不能手改生成物：
  - `all_mastered` 判别空态、分量、实际解锁数和 `graph_version`；
  - `ProgressEntry` 的有效 `status`、可空 `own_status`、`inherited_from[]`（`{kp_id, status}`，只列未被覆盖的来源）、可空 `updated_at`；
  - `GET`/`PUT` 都返回 V 中每个节点。

  未发布使用 A04 的 404，已提交空图使用 5xx 完整性错误，不新增 `no_graph`。当前 `RecommendResponse` 和 `ProgressEntry` 还不足以表达这些语义，本 A08 不改接口文件。B08 须确定学生读路径完整性错误的公开错误码，响应只含诊断 ID。
- **数值与参数**（决定 5～7）：`importance/difficulty` 的 `[0,1]` 范围沿用既有候选契约与 A04 快照。属性缺失时取中性值 0.5。权重来自四个 `RECOMMEND_WEIGHT_*` 环境变量，缺省为 S2 值，全站统一，不做课程级配置（见 §1）。推荐显示上限默认 10、最大 50。环境变量登记在 `.env.example` 与 `docs/integrations.md`。
- **细则 1：显式写入覆盖继承**（决定 9）：以来源“本次连续归属”的起算版本为界，规则见 §5，验收见 LP-18、LP-20。实现依赖：进度行增加写入序号（C01/I01），版本提交事务从同一序列取提交序号（G05，须随下条的 ADR-012 修订一并规定）。
- **细则 2：谱系存放位置**（决定 10）：谱系作为发布快照节点的 `merged_from` 字段保存，按绑定 `version_id` 读取，回滚复制源快照时谱系随之回退。**实现前须先修订 ADR-012**（由 A04 负责），规定字段形状（包括链式来源与直接父子关系）、摘要纳入方式和提交序号，然后才能交 F10/B11/G04/G06/I01 实现；不能由 I01 从当前草稿或名称推断谱系。
- S2 §6.4.7 的“目标导向路径”与学习材料生成属于加分项；O01 未批准前，本规格只覆盖“下一步”候选列表，不承诺目标路径 API。
